# DJ Music 改版设计与验收计划

日期：2026-11-19。当前基线为已发行的独立版 0.5.0/build 8。GitHub 项目归属继续使用 Dingjian 名称（当前远端 URL 暂时保持），面向用户的 Windows 与 Android 产品显示名统一为 DJ Music。本文以《乐音音乐-改版评估.md》为路线输入，记录功能现状与后续改版方案；不是实现或发行承诺。

## 背景与目标

0.5.0 的主导航是搜索、QQ 音乐、网易云、酷狗、我的；用户按平台切换收藏列表，搜索一次只查一个来源。发现、推荐、榜单、歌手/专辑、听歌统计、智能歌单、备份恢复、均衡器与睡眠定时等实现分散在仓库模块中，但并非都挂在独立入口。关闭窗口行为、窗口状态、托盘和全局媒体控制等桌面工作也需要分别核实，不能由共享源码推断成品可用。

目标是保留用户数据和既有播放、下载、账号行为，把独立版导航改为“首页 / 搜索 / 我的音乐 / 我的”，接好发现、按平台独立汇总搜索、跨平台曲库、已有详情与个人能力，并补齐 Windows 日常控制。Mconnect 默认入口继续使用 Mconnect 品牌及原资源，不重写其生产入口。

### 品牌与兼容边界

产品标题、桌面快捷方式、Windows 安装器、Windows 文件描述、Android 启动器、设置页、字体预览、Android 26+ 通知频道及空曲目回退媒体项均显示 DJ Music。Android 独立版的小组件描述与无曲目文案也显示 DJ Music；Mconnect 继续使用原文案。Dingjian 用于 GitHub 账户/组织或项目归属表达，不在客户端产品界面混入第二个品牌。旧的“乐音音乐”“悦音音乐”“Meizuo Music”“MZ Music”快捷方式仅在能够确认目标属于本应用时清理，并且仅删除已核对的快捷方式文件。

兼容身份固定不动：Android applicationId、release 签名、Windows AppId/AppUserModelID、`yueyin_music.exe`、Windows CompanyName/ProductName（`sun-dove` / `YueyinMusic`）、安装目录及现有数据库/Hive 键均保持。Windows 账户数据目录由 CompanyName/ProductName 推导，改其值会让既有 0.5.0 数据看似丢失。0.5.0 发行记录不重写；0.5.1 build 9 才是新品牌首个兼容版本。

用户提供的 `D:/WorkSpace/Projects/music-app-icon` 图标源已归档到 `assets/branding/dj-music/source/`。Windows 与 Android 使用该纯音符渐变图形；通知栏保持 Android 所需的白色单色小图标，Mconnect 的共享图标资源不变。当前仓库发行目标是 Windows x64 与 Android，iOS/Linux 资源归档保留，但不声称仓库具备相应发行流水线。Android 的自适应图标、monochrome 图层、独立启动背景及小组件文案按资源目录隔离，不能替换 Mconnect 默认入口的共享资源。

0.6 首轮功能只重组独立入口，并复用已有平台接口、状态提供者、页面及数据库。没有验收门证明数据兼容前，不新增收藏/统计/歌单数据库迁移。网络结果、账号态、页面状态经现有 provider/registry 作用域组合接入，不另造播放与下载后端。

## 方案比较

### 方案 A：新建 DJ Music 专用路由和根页面

在 `video_app` 内新增视频版 GoRouter 和应用根壳，使用当前独立版 `ProviderContainer`、平台注册、数据库及 `VideoAuthNotifier`。四个主区使用四个常驻页面，子页面按显式路由打开。逐个把已有页面的依赖与跳转纳入这套路由和作用域。

优点：已有 `context.push` 模块可以以适当依赖复用；播放页、壳层和产品入口仍由 DJ Music 管理。职责清楚，Mconnect Router 与 Shell 不受牵连。缺点：必须验证 provider 生命周期、路由跳转及独立播放器/通知行为，初期接入成本较高。

### 方案 B：保留五页壳并把每项能力改成回调

继续使用 `MaterialApp(home:)` 和页面索引；将 Mconnect 功能页跳转改成参数回调，把统计、榜单等塞进现有壳或弹层。

优点：少改 Router 基础结构。缺点：每个页面多一套独立跳转接口，导航、深层详情、返回状态与弹层分散；已有 `context.push` 仍无法工作，功能越多，重复改造越多。

### 推荐方案

采用方案 A，建立隔离的 DJ Music 路由和入口壳；旧 `VideoMusicApp` 构造参数及 Mconnect 路由保持向后兼容。路由用例作为接入前的确定性红门；页面体验门逐个描述用户看到的成功、部分失败、未登录、不可用和空状态。首页、搜索、曲库先组成可独立验收的 0.6 场景，再扩展桌面与个人数据能力。无法在 DJ Music 的 Auth/Player/Database 作用域下正常工作的旧页面，先新增隔离适配，不改变 Mconnect 行为。

TypeSafe Jev `jev-1.14.0` 对阶段顺序选择阶段 A，概率 1.0、confidence 1.0。它仅辅助排序，不替代代码核对、用户审阅或功能验收。

## 信息架构和状态设计

### 主导航

| 主区 | 用户任务 | 进入后的首要内容 |
| --- | --- | --- |
| 首页 | 快速找到下一首歌 | 继续播放、每日推荐、榜单和新歌入口；区域数据各自有加载/失败/重试状态 |
| 搜索 | 一次查多个来源并选可播放版本 | 本地、QQ、网易云、酷狗分组结果；筛选只改变显示，不重发整份请求 |
| 我的音乐 | 管理收藏与个人库 | 聚合的来源收藏和本地收藏；平台筛选；歌单、本地音乐、下载、最近播放入口 |
| 我的 | 账号与应用维护 | 平台账号、播放/下载设置、音源、缓存、主题背景字体、统计、智能歌单、备份、音效和版本 |

Windows ≥ 840 logical px 使用侧栏导航；窄窗口/移动端使用四项底栏。播放器和迷你播放器继续由独立入口自己的壳管理。桌面队列右侧常驻属于播放器阶段，基础 IA 不静默改变既有行为。

### 搜索结果模型

按平台维护独立状态：`queryGeneration`、`platform`、`songs`、`page`、`total?`、`hasMore`、`loading`、`loadingMore`、`errorKind?`、`retryable`。本地检索、QQ、网易云、酷狗并发启动，各来源超时/失败不阻塞其他来源。筛选“全部/本地/QQ/网易云/酷狗”只过滤已获取状态；单来源重试及加载更多只作用于该来源。查询代次不匹配的迟到响应丢弃。

首次结果按来源分组；歌曲 identity 使用 `(platform, songId)`，不同平台的同名/同曲不自动合并，避免误把会员权限、音质和下载来源折叠掉。后续跨源匹配须单独新增可执行门和解释反馈。

各组明确呈现加载、成功条数/总量、暂不可用/登录要求、空结果、失败类别与是否可重试。加载更多使用来源自己的分页游标。全部失败显示汇总错误和重试；部分失败保留成功来源及失败来源入口，不显示“已完成全部搜索”。

### 我的音乐与推荐内容

聚合以歌曲平台 id 保留来源，不合并不同平台实体。平台“我喜欢”列表的缓存继续由各平台账号拥有；应用内本地收藏继续由本地数据库拥有。共同收藏页保留“平台收藏 / 本地收藏”来源标识及独立写操作；移除某平台收藏不得删除本地收藏或其他平台收藏。未登录来源展示登录入口，分平台同步时标记局部进度，失败时保留已有条目并允许重试。

首页聚合区与榜单/新歌不得把“不支持该地区”“未登录”“无数据”和“网络失败”压成同一空白。仅展示 provider 返回的能力；未经验证不制造推荐数据或宣称各平台都有榜单/新歌。

### 路由与作用域草案

根入口 `/` 以 `tab` 参数或稳定 tab 标识映射四个主区。子路由包括 `/recommendations`、`/toplists`、`/toplist/:platform/:id`、`/new-songs`、`/album/:platform/:id`、`/artist/:platform/:id`、`/playlist/:platform/:id`、`/history`、`/local-music`、`/downloads`、`/listening-stats`、`/smart-playlists`、`/smart-playlists/editor`、`/backup` 与现有账户/音源/外观页面。先核对路由目标是否真实存在；差异通过适配或显式空状态解决。

新增所有可选构造参数提供旧值兼容默认。收藏/搜索状态保留来源字段，不在路由迁移时重写数据库。播放器、登录会话、下载任务与旧音质偏好沿用现有容器和存储键。

## 场景与验收门

每行是单独的真实场景。确定性门验证数据、错误类别、路由和状态不变量；体验门验证可见页面、按钮状态、提示和失败后的动作。新场景先在 0.5.0 基线上新增断言并记录预期失败，再实现到绿。旧的播放、下载、账号和兼容门持续保留。

| 阶段 / 场景 | 功能门：先红后绿 | 体验门：先红后绿 |
| --- | --- | --- |
| 0.6 用户在任一来源搜索 | 同查询触发四来源；单源失败保留其他响应；页码各自递增；迟到响应不覆盖新词；重试只调目标来源 | 全部/部分失败、逐来源加载/分页和筛选可读可点；空结果、未登录与不支持状态有不同说明 |
| 0.6 用户浏览聚合收藏 | `(平台,id)` 稳定唯一；本地收藏和平台收藏写操作隔离；同步部分列表与完成状态准确；账号变化清除旧账号列表 | 未登录可进入登录；同步中显示进度；中途失败可重试，已有结果不闪成空白；平台筛选正确 |

| 0.7 Windows 用户恢复窗口及媒体操作 | 尺寸边界和位置读写；媒体键正确触发；缩放/最小尺寸/窗口恢复和队列状态一致 | 重启恢复合法尺寸；窗口不越界/挤压；键盘媒体控制只影响本实例；桌面队列不遮主要内容 |
| 0.7 用户启停悬浮歌词 | Windows 原生通道调用、歌曲切换更新、关闭/退出清理、缺能力返回类别确定 | 开启后可见；系统/宿主拒绝时有提示和重试入口；关闭后无残留窗口 |
| 0.8 用户看统计、建智能歌单、备份 | 分别验证 provider 注入、历史来源、规则读写/预览、备份导入确认和数据兼容；失败不破坏库 | 每个入口可达；加载/空/失败/成功反馈齐全；导入前预览与二次确认可见 |

## 版本分解

**0.5.1：品牌与图标兼容更新。** 产品全名统一为 DJ Music；Windows x64 与 Android 替换为提供的图标，Windows/Android 显示名、版本标签、安装器和独立通知品牌同步。Windows AppId/AppUserModelID、EXE、CompanyName/ProductName 和数据目录不动；Android applicationId、稳定签名、旧通知 channel ID 不动；Mconnect 默认入口、资源和行为保持。必须通过品牌/资源/身份门后才能发布。

**0.6：入口与常用场景。** 新建 DJ Music 隔离路由/壳和作用域红门；通过后推出四主区、聚合搜索、我的音乐、首页/榜单、新增详情与个人库入口。重排 9–11px 次要文本并在 1186x793 与 DPI 矩阵复核可读性和溢出；文案继续集中在 l10n。不能把 0.6 简化为只换标签。

**0.7：Windows 桌面配套。** 依赖 0.5.0 已选择的关闭偏好，逐项加入托盘、窗口尺寸恢复、单实例、最小窗口尺寸和媒体控制。悬浮歌词有独立原生/体验门；队列右侧常驻与当前底部弹层替换需要桌面 UI 验收。

**0.8：个人数据和音效。** 接入听歌统计、智能歌单、备份恢复、均衡器和睡眠定时。复杂编辑和导入先建立数据边界、失败恢复、确认与回滚测试。

每个版本分支新增中文追踪与用户可见变更记录，并以当前独立入口验证；不把三个版本功能堆到一起再首次运行。

## 接入步骤与回滚

1. 品牌与图标票据已按用户选择 DJ Music 更新；0.5.1 的品牌工作按本票据验收。
2. 进入 0.6 功能编码前，需用户审阅四导航、目标稿和 0.6 功能范围；按项目设计门先编确定性/体验断言并在 0.5.0 基线上记录红门。
3. 增加 DJ Music 独立 Router 与 RouteShell，保持旧 `VideoMusicApp` 使用方式、Mconnect appRouter 及全部既有公开契约；每接入一个模块即运行相邻门。
4. 运行格式检查、`flutter analyze --no-pub`、定向测试和完整 `flutter test --no-pub -j 1`。路由/背景/底部布局断言须完成真实红到绿。
5. 由既有发行流水线制作 Windows 与 Android 三 ABI；核对签名、版本码、稳定身份、关键数据文件与登录态。真实服务/API/音频播放不以 mock 或 widget test 代替。

品牌回滚为发布更高兼容补丁，恢复独立入口旧品牌资源，同时保留 Mconnect；不更改身份或用户数据。0.6 路由回滚时停用改版入口并恢复 0.5.1 页面组装，不删除或逆向迁移设置/数据。

本稿推荐先做 0.6 整体场景改版。评估文档没有模块实现协议时，以现有服务诚实显示不支持和失败，不虚构后端能力。
