# IK Music 3D 音效实施记录

日期：2026-11-20。用户已确认桌面重设计与小型 HRTF 方案，授权继续改版、构建与发布；本票据记录 U07。版本、安装与发布由主任务统一执行。本任务不清理既有产物。

## 范围、兼容与回滚

新增可选空间能力接口、独立 ik 空间运行时与共享原生 FIR 核心，旧接口签名和缺省关闭行为保持。Windows 处理节点编入同一个 libmpv 所链接的 FFmpeg 音频滤镜；属于设计方案 B 的原生处理节点，避免第二套解码器。Android 通过受控 just_audio 原生 AudioProcessor 薄适配复用同一 C 核心。主界面、_SourceAudio 包装、音频服务包装、独立应用构建脚本是受影响调用方。撤销独立运行时装配、恢复固定原 DLL/插件即可回滚，用户空间设置保留但不启用。

实际声音和 UI 状态分开验收。`af`设置返回成功不算生效，需原生处理节点报告当前请求代次与真实处理帧数。应用设置失败时请求恢复最后有效配置；播放期间发现处理失败则请求关闭空间节点，界面保留失败提示，不能把回滚请求当成回滚已证实。切歌/seek 清除卷积尾音，EQ 与空间链由同一后端合成。禁止用 Haas/声像/音量变化冒充 HRTF。

## 资产与构建

采用 MIT Media Lab 的 Bill Gardner、Keith Martin 于 1994 年实测 KEMAR diffuse-field HRTF；官方许可允许研究和商业使用，要求署名。原始归档固定 SHA-256 `A48E73137390626EF1E45D1DE6A4D98530C6AA570E71B40F7C4442241ED5FA22`，来源 `https://sound.media.mit.edu/resources/KEMAR/diffuse.zip`。许可原文保留在 `native/ik_spatial/data/MIT-KEMAR-LICENSE`，产物必须带署名。HRTF 处理不增加完整 ffmpeg 命令程序。

本机已有 WSL Ubuntu 24.04、GCC 与 Android NDK 28。补齐 WSL MinGW/meson 工具链，不安装 Visual Studio。构建工具及下载缓存属于开发环境，不进入安装包；Windows 新 DLL+资产必须不超过原 DLL 15,525,902 字节加 2 MiB。依赖源代码与构建固定版本和哈希，产物需信号验证后才接入。

## 验收门与进度

先建立 `native/ik_spatial/ik_spatial_gate.c`，实现前缺少 `ik_spatial.h`，编译红门确认没有现成能力。该正式门覆盖全部拟支持方向、两采样率、左/右输入脉冲、黄金卷积、0/关闭旁路、25/50/75/100% 强度、seek 清尾、非法参数与真实帧计数；产品接入还需播放器链、EQ组合、状态/回滚、包体门。门代码是正式交付，不是临时测试。

### 确定性核心与运行时

- 共享 C 核心共 296 项门：Ubuntu GCC 与 Android API 30 x86_64 模拟器上的 NDK 可执行文件均通过。所有拟支持方向均执行，没有抽样截断。
- Dart 的空间状态门先因能力与运行时文件缺失而红，补实现后，与多音源包装、Windows 控制器共 13 项定向门通过。有效状态必须同时匹配本次 requestId 与大于零的 processedFrames；不支持、设置失败、迟到旧报告分别检查。全仓检查由主任务汇总。
- 系数覆盖 24 个方位、3 个仰角、双耳、256 taps、44.1/48kHz，编译后的系数为 294,912 字节。双声道虚拟源分别位于参考方位左右 30°，方位和仰角连续插值；20ms 系数过渡，干声延迟对齐，结果限制在 PCM 合法范围。

### Windows 真实输出

真实 `libmpv-2.dll` 在本机通过以下门：

1. WAV 解码、两种采样率、前/侧/后/上/下方向及 EQ 组合，共 12 项。输出为真实 float PCM，检测能量和方向差异，并查询当前请求的原生处理帧数。
2. 独立读取原始 MIT WAV 数据，逐点比较两种采样率、左右输入源、双耳的 256 tap 脉冲响应，最大容许误差小于 `2e-6`；不用生成后的同一张表充当唯一真值。
3. WAV、FLAC、MP3、AAC/M4A、Vorbis/OGG、Opus、DTS、WMA、HLS，共 9 种输入，各自经过本地文件与本机 HTTP 两条路径，均组合 EQ、HRTF 与 1.25 倍速，共 18 项通过。FFmpeg 可执行程序只生成验收素材，不进入安装包。
4. 关闭播放器后处理帧读数清零，避免后续实例显示上一个滤镜的残留成功状态。

本机构建 DLL 为 8,483,840 字节，SHA-256：`A6B46A3F1AEA294E7AFBC81B1DF5B1C23C40577A7D7A90677067B2289CFC6A2A`。原 DLL 为 15,525,902 字节，新版低于“原版加 2MiB”的上限。仅依赖 Windows 系统 DLL，没有增加动态 `libwinpthread`。发行 CI 应重新构建并对实际发行产物运行同样的门；本机散落开发 DLL 不作为提交内容。

开发中实际定位并修复了两个阻塞：原裁剪 DLL 缺少所需滤镜；mpv 0.36 同步读取 `af-metadata` 会重入核心锁并触发断言。最终通过共享库导出的无锁原子查询处理帧，不再调用该元数据属性，保留 mpv 自身断言检查。

### Android 适配与边界

Android 在隔离的 just_audio 0.9.46 副本中增加 Media3 PCM AudioProcessor，关闭音频 offload，让数据经过共享 JNI/C 核心；不修改 Pub 缓存。仅接收 44.1/48kHz、单/双声道、16bit PCM，其他格式明确报告 `format_unsupported`。通道报告请求代次、实际帧数和错误；前 4096 帧的左右声能诊断用于真实设备门。

`scripts/spatial_device_gate.dart` 是显式 target 的正式验收入口，生成左声道正弦、右声道静音的 WAV，在真实 just_audio → Media3 → JNI 链中验证右耳产生卷积输出，然后检查强度/方向修改、seek、停止后重载与关闭。它不会由产品入口自动执行。

### 许可与尚未覆盖的场景

固定源归档、SHA 校验、补丁和构建脚本一并交付；Windows 安装包随 DLL 带 FFmpeg、mpv、FreeType、FriBidi、HarfBuzz、libass、MinGW/GCC 与 MIT KEMAR 共 16 份许可/构建说明。Android 把 KEMAR 署名附加到隔离插件许可，供 Flutter NOTICES 收集，保留原插件许可。对应可重建的第三方源归档由发行流程提供。

这里的 HRTF 为通用 KEMAR 耳机双耳渲染，不承诺每个人的定位听感，不包含头部追踪、Atmos 对象解码或外放多声道。当前设备播放验证环境为 x86_64 模拟器；ARM 实机耳机听感、蓝牙延迟和持续功耗尚未验证，不能据编译成功宣称这些场景已验收。
