# IK Music 内置音源接入设计

日期：2026-11-20。状态：只读调研与待讨论设计，尚未实施产品代码或新增测试。用户新增要求是自动整合指定的 `pdone/lx-music-source`，无需逐项手动粘贴链接。本文件不替代桌面重设计稿。

## 一、目标与既有边界

首次打开后自动准备音源；用户看到准备进度、已准备数量与每项失败原因。再次启动不重复添加，不恢复用户禁用或删除的音源。无网络仍可进入应用，已准备的本地脚本继续保留；网络恢复后能重试。更新使用审查过的固定清单、逐文件校验、独立回滚，不在每次启动跟随上游 `main/latest.js` 漂移。

“内置”在本设计中指内置目录与自动准备能力。现有证据不足以把整个第三方仓库的脚本直接装进安装包，也不足以承诺所有来源都能播放。音源脚本许可、其所访问服务的使用范围、实际音乐内容授权是不同事项；本设计不把技术兼容或脚本下载解释为已获内容授权。

旧 Mconnect 入口、既有公开方法、旧导入行为和已有账号数据不变。新增能力只从独立 `main_video` 装配，旧入口不启用新协调器。用户此次要求更新了此前“不自动预置”的产品范围；它没有证明任何第三方作者的分发许可。

### 2.2 分发许可结论

- 聚合仓库 GitHub 元数据 `license=null`；完整树未发现 `LICENSE`、`LICENCE`、`COPYING`、`COPYRIGHT` 或 `NOTICE` 文件。README 只写“洛雪音乐源，内容源于网络”，提供在线导入地址和来源链接，没有仓库级重新分发授权。
- 四个脚本的 MIT 头是有价值的逐文件证据，不能扩大为对其余 16 个文件的授权，也不能自动覆盖这些脚本内可能合入的第三方部分。
- [杰翔原作者 LICENSE](https://github.com/haonanren118/jiexiang-Music-Source/blob/4f575068f7b774294d5bc28a4e752f8098f9f813/LICENSE) 提供 MIT 正文，要求保留版权与许可声明。但该原作者提交中的历史 `2.3.0` 文件为 62,444 字节，聚合仓库副本为 91,493 字节，不能仅凭版本名相同认定二者完全一致并代替副本来源核对。
- `HYWmusic_source` 及 `Huibq/keep-alive` 当前仓库元数据亦无可识别许可证；这不抹去 HYW 文件自己的 MIT 头，但不能据此宣称整个来源链均已核清。
- `xinghai` 的学习交流表述不是通用分发许可；默认日常自动启用不应擅自扩大该范围。`huibq`、`yuningxi` 的批量下载限制必须作为明确限制保留，不能通过启用应用的下载开关来规避。

结论：当前不能宣称“20 源均获准随包分发”。本设计推荐不携带第三方脚本副本的方案 B，并保留逐项许可证据。由用户明确指定地址触发的本地下载也不是许可证据，不能在 UI、README 或发布说明写成“全部开源已授权”。

## 三、方案比较与推荐

| 项目 | A：随包固定脚本与目录 | B：随包固定清单，首次受控下载 |
| --- | --- | --- |
| 首次操作 | 无需粘贴、可离线准备脚本文本 | 无需粘贴；后台自动获取，有网络后完成 |
| 离线第一次启动 | 文本存在，但脚本初始化仍可能要联网 | 目录可见，显示待联网；本地音乐、官方已有能力继续工作 |
| 发布内容 | 安装包实际重新分发第三方脚本 | 安装包只含来源、固定版本、哈希、限制与状态元数据 |
| 当前许可适用性 | 不能直接覆盖全部 20 源；需逐文件补齐分发依据及 NOTICE | 不复制未核清的第三方文件进发布包；仍如实保留来源条款 |
| 审查/更新 | 应用版本锁定；更新需新包或额外更新通道 | 同样锁定审查清单；可后台获取已批准版本，不追随任意 upstream 内容 |
| 失败模式 | 安装包变大；服务端仍可能失败 | 首次网络不可达、哈希不符、初始化失败须逐项可见 |
| 回滚 | 切回已知脚本副本 | 保留上一已确认版本和配置，单项或清单回滚 |

推荐 **B**。它满足“不再手动添加”，当前不会把全部脚本当作已获分发许可复制进应用。A 保留为将来逐项核清授权后的选项，不能本轮直接将 20 个文件加入 assets。

第一版只从随应用签名发布的本地清单决定候选，不接入新的在线目录发布服务。设置中的“检查更新”检查本地清单是否比已安装记录新，以及重试待获取项；没有更新过的审查清单时显示“已是当前目录版本”，不要暗中下载 `main/latest.js`。清单随下一应用版本更新后自动准备对应版本。远程清单、独立签名和撤回服务可另立场景，当前不引入。

推荐的初始策略：全部 20 条在目录中可见；Windows 对既有 16 个兼容候选进行当前设备校验，已知不支持/失败的四项清楚显示原因，不重新运行来冒充新能力。`xinghai` 保留许可范围说明，暂不自动启用；其余许可缺失项也不得显示“许可已验证”。Android 使用自己的实际运行时记录，不能复制 Windows 绿色状态；未执行的项目显示未验证。真实初始化通过且没有明确使用限制冲突的新条目可自动准备为播放候选，不需要粘贴或逐项导入。下载缺省关闭，两个明确限制批量下载的来源不纳入自动下载范围。

新安装且没有任何手动源、旧 HTTP 源或源策略时，可采用“官方优先、自动尝试已启用候选、不擅自升档、第三方下载关闭”的初始策略。升级用户已有的首选、排序、启用、音质、自动切换、官方/音源优先和 HTTP 设置全部保留。自动准备完成与自动改写用户策略必须分开；既有策略不足以使用全部候选时，应清楚提示已准备情况并提供一次策略操作，不能静默替用户开启“音源优先”。

## 四、现有代码接入事实与必须避开的坑

| 现有位置 | 可复用能力 | 新接入注意点 |
| --- | --- | --- |
| `lib/main_video.dart` | Hive、`WindowsSourceSettings`、V3 引擎、受控网络与独立播放器装配 | 只新增独立自动准备协调器；先显示应用，不 await 全部网络 |
| `LxSourceImporterV3.importLink` | HTTPS 下载、备用同文件地址、1 MiB/30 秒上限、能力识别 | 当前顺序是下载→执行 inspect→计算文本 SHA；不能把它直接当“先验固定哈希再执行”的入口 |
| `LxSourceRuntimeV3` | Windows/mobile 环境、取消、限时、受控网络桥 | 继续真实设备环境；初始化不代表曲目播放或实际音质 |
| `SourceCollection.upsert` | 同 origin 更新保留 enabled/download 开关 | ID 是 origin URL 的 SHA；换提交 URL 会生成新 ID，必须额外维护稳定目录身份 |
| `SourceSettings.save` | 集合持久化、首选镜像和通知 | 保存启用 LX 首选会关闭旧 HTTP 配置；有旧 HTTP 用户不可自动触发这一迁移 |
| `MultiSourceVideoPlayerNotifier._settingsChanged` | 配置变化取消旧代次与解析 | 每次发布还可能暂停当前受管播放；不能逐个下载完成就 save 20 次 |
| `SourceManagerPage` | 搜索、筛选、排序、检测、启用、下载、未保存离开保护 | 页内维护初始快照草稿；后台发布会与用户保存相互覆盖，需要编辑租约或合并门 |
| `SourceCheckStore` | 记录 entryId+脚本哈希+runtimeId 的初始化结果 | 记录可丢弃，不能用它当唯一已安装/禁用依据；原生运行时变化后必须重新校验 |
| `WindowsMusicPreferences.setQuality` | 音质事务会同步更新源策略 | 自动合并与用户改音质要走同一独立写队列，不能拿旧 collection 全量覆盖 |
| `BackupStore` 的 settings 快照 | 备份已有集合、配置与脚本文本 | 新目录身份/禁用墓碑放 settings 可随备份；恢复后不把旧设备检查记录直接当当前设备通过 |

新增固定版本导入器必须先按原始响应字节计算期望 SHA-256，再进行严格 UTF-8 解码和沙箱 inspect。字节哈希与既有 `LxSourceConfig.sha256` 的“去 BOM 后 UTF-8 文本哈希”分开记录；二者语义不能混用。哈希失败时引擎调用次数必须为零。脚本 URL、提交和期望哈希全部由应用内清单给出，不接受脚本自己提供的更新地址。

现有安全边界继续生效：只允许公开 HTTPS；拒绝私网、环回、重定向及不受控 HTTP；不注入用户账号 Cookie；不开放 Node/Electron 或文件系统宿主对象。V3 初始化限时 15 秒、单次总请求 32、并发网络 4、响应 512 KiB、请求体 64 KiB，新增自动流程不提高这些上限。初始化阶段可能联系脚本自己的外部服务，应在音源页说明这一点；不能称为单纯离线文本导入。

## 五、接口与数据设计

以下是设计契约，尚未新增源码。中文 UI 文案集中在 l10n。

### 5.1 随包清单

新增 `assets/source-catalog/pdone-v1.json`，只包含元数据。发布检查要求恰好覆盖此次确认的 20 目录，各自有明确 `autoPolicy`，不通过省略失败项来美化结果。

```text
目录清单
  schemaVersion: 1
  catalogVersion: 本应用审查版本（递增整数）
  repository: pdone/lx-music-source
  commit: 固定40位提交
  entries[]:
    sourceKey: pdone:<目录>              # 跨脚本版本不变
    displayName: 显示名
    path: <目录>/<固定版本>.js
    byteLength: 精确字节数
    contentSha256: 原始响应字节SHA-256
    licenseEvidence: none/headerMit/restrictedText
    licenseNote: 证据及来源链接，不写推断授权
    autoPolicy: prepare/metadataOnly
    reason: metadataOnly必须说明原因
    perRuntimeEvidence: 已有矩阵结果，仅作历史证据
    downloadsAllowed: false            # 首次缺省；明确限制不得自动放开
```

四个 MIT 头及原作者许可证据也需保留准确链接/版本。若以后启用随包脚本，另增加完整 NOTICE 与来源对应证明，不能将本清单字段直接当分发许可。

### 5.2 本地记录

使用新增独立 settings 键保存 `ManagedSourceState`，既有 SourceCollection schema 不变。新增字段均由新模块读取；旧版本忽略它们。

```text
ManagedSourceState
  schemaVersion: 1
  catalogVersion: 已知目录版本
  revision: 本地写代次
  managed[sourceKey]:
    entryId: 既有SourceEntry.id
    origin: 真正固定提交URL
    contentSha256 / scriptSha256
    activeVersion / previousVersion
    userDisabled: 是否明确关闭
    userRemoved: 是否明确删除（墓碑）
    userDownloadsChoice: 用户已选值，不能被新缺省覆盖
    stage / failureCode / checkedRuntimeId / checkedAt
  pendingCommit: 可恢复的待发布操作（如存在）
```

脚本文本继续放既有 `SourceCollection`，不再另存一套相同正文；仅保留当前版本与最近一个可回退版本。第一版总内容预算 8 MiB、单文件 1 MiB，超过即整项拒绝；本次 20 源正文约 1.49 MiB，预算是明确上限而非自动解禁容量。没有完成的下载只在内存，取消即释放，不遗留 `.part` 或临时执行脚本。

识别目录来源只接受已知仓库的正规 raw URL、等价 GitHub blob URL或清单明确列出的同文件 CDN URL，并核对路径和已知哈希；不凭音源显示名相同合并。已有用户手动导入的 `main/<目录>/latest.js` 命中身份时沿用 entryId、顺序和开关，登记为已有条目，不追加第二份。下一版本使用 `replace(existingId, newConfig)`，不对新提交 URL 直接 `upsert`。自定义同名源仍独立。

### 5.3 新增协调器契约

```text
IkSourceCatalogCoordinator
  prepareOnce()              # 幂等、后台、可取消
  retry(sourceKey?)          # 只重试可重试失败，不复活用户删除/禁用
  prepareCatalogUpdate()    # 仅使用应用当前固定清单
  rollback(sourceKey?)      # 切回明确的已确认版本
  suspendPublishing()      # 管理页/音质编辑租约；下载可继续，暂不覆盖草稿
  resumePublishing()
  commitAtPlaybackBoundary() # 新播放开始前发布一批，绝不逐项暂停在播歌曲
  dispose()                 # 取消请求、丢弃迟到响应
```

`prepareOnce` 必须按 sourceKey+目标哈希单飞；并发调用返回同一操作。网络获取建议并发 2，沙箱初始化串行 1，避免首启创建多个 Windows WebView2 进程及突发第三方请求。每项沿用 30 秒获取预算和 15 秒执行预算，逐项完成更新进度，首个成功项不等最后一个失败项才显示。全目录没有固定“全部成功”假设。

## 六、运行流程与兼容性

1. `main_video` 先加载已有配置和目录元数据，恢复未完成的提交记录，不联网。创建 V3 引擎及新协调器，完成首帧后异步 `prepareOnce`。
2. 已存在且哈希一致、未撤回、当前运行时已有有效检查记录的条目不重下、不重执行。旧检查记录的 runtimeId/哈希不同则显示待校验；离线时保留缓存并说明未重新验证。
3. 每条目标先下载固定 URL→核对字节数与 SHA→严格解码→既有受限引擎 inspect→确认支持平台/档位→置为待发布。`grass` 或明确政策不允许项保留目录状态而不创建假可用配置。
4. 初次没有当前曲目时可合并发布一批；用户已开始播放则先保持准备结果。新增独立播放器装配钩子在下一次明确的新播放请求进入既有 `_start` 之前等待同一写队列发布，随后由旧播放器正常建立新会话。它只作用于 IK 的新增封装，旧播放器方法和缺省行为不改；不依靠每秒轮询或在当前播放期间反复 save。若该钩子的时序不能证明安全，第一版仅下次启动发布待更新内容，并在 UI 明确“已准备，下次启动生效”，不可伪称已启用。
5. 所有 IK 源写入，包括管理页保存、自动发布、回滚及音质联动，进入同一新增串行协调边界；以提交时最新集合做增量合并。不能只把底层 Hive 写入排队，因为上层可能已捕获旧快照。管理页打开时持有发布租约，退出保存或放弃后释放；保护用户尚未保存的开关与排序。
6. 集合、目录身份和删除墓碑须具备同一提交恢复语义。推荐新增独立受管保存入口，用同一次 Hive `putAll` 写入集合、现有首选镜像和目录状态；旧 `SourceSettings.save` 不改。若复用两阶段写入，必须先写包含预期前后 revision 的日志，启动依据实际集合哈希补全或回退，不能以“写两次通常都成功”代替一致性门。
7. 明确删除受管源写墓碑，更新和重试不再添加；停用只保留条目与禁用选择。“恢复内置目录”是明确用户操作，列出将恢复项目，不在后台悄悄清墓碑。已有手动源、旧 HTTP 源、首选和顺序不被目录初始化覆盖。
8. 备份包含受管元数据和墓碑；恢复后与集合按 entryId/hash 对齐。恢复来自另一运行时的检查只作历史，当前实际校验前不显示“本机通过”。损坏元数据不得删除已有集合；显示恢复提示并按已知源身份重建最小索引。

### 体验状态与操作

| 状态 | 用户看到 | 允许操作/后端要求 |
| --- | --- | --- |
| waitingNetwork | 等待联网，已保存源仍可用 | 重试；不占据启动遮罩 |
| downloading / checking | 正在准备 n/20，当前条目 | 取消；细分获取与初始化，禁止重复开跑 |
| ready | 本机初始化通过，可参与尝试 | 保留声明能力，不写“保证可播放” |
| pendingApply | 已准备，等待安全时点生效 | 当前播放不暂停；清楚说明生效时机 |
| partial | 已准备 n 项，m 项待处理 | 展开完整20项，针对失败重试 |
| unsupported | 当前支持平台不匹配/环境不支持 | 不提供无意义重试，保留原因 |
| restricted | 使用范围待核对或不允许当前用途 | 展示证据；不自动开启下载或日常播放 |
| rateLimited / download / timeout | 请求受限/下载失败/超时 | 有限退避，手动重试；不无限重试 |
| integrity / invalidEncoding | 文件内容与固定版本不符 | 不执行；仅检查应用目录更新或恢复已确认版本 |
| disabled / removed | 用户已停用/移除 | 不被更新覆盖；恢复须明确操作 |
| rolledBack | 已恢复到具体已确认版本 | 显示目标版本及时间，保留用户策略 |

运行时 HTTP/私网拦截继续给明确原因。`sixyin` 不因用户要求自动添加而放开 HTTP；`juhe` 不因超时而绕过服务限流；`changqing` 的 Windows 历史失败不改写成 Android 失败。上游健康图只作外部参考，不作为本机已通过状态。

## 七、固定版本更新与回滚

更新只发生在清单版本前进且目标内容哈希变化时。先准备新版本并在当前环境完成检查，再保留旧活动版本、合并用户选择，在安全边界切换。新版本失败保持旧版本继续使用；网络失败、脚本失败、写入失败分别记录，不清旧集合。

回滚的单位是稳定 sourceKey。恢复上一已确认正文、origin、能力声明与匹配的检查证据；当前用户禁用、下载许可、排序、首选继续保留。全目录回滚也只触及受管条目，不删除手动源。应用降级读取旧 SourceCollection 不受新元数据影响；如果配置版本超出支持范围，新协调器停用自身写入并保留数据，不“修复”为清空列表。

技术开关关闭新协调器即可回到现有手动管理；已写入的兼容集合仍可被旧入口读取。不删除旧数据文件，不迁移应用 ID、账号或存储目录。首次自动准备造成的默认策略必须有单独快照，只在用户未进一步改动时才允许回滚该初始策略。
