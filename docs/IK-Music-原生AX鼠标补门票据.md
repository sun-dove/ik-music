# IK Music 原生 AX 鼠标路径补门票据

## 真实问题与授权

本轮用户要求继续完成改版、安装和发布，包含成品缺陷修复。产品提交 `6a5c5ed816bb1a600616ae15db518832f87e388a` 的 Windows 成品在原目录保护升级后，于首启验收出现 `Failed to update ui::AXTree`，错误为节点 `208`、`270`、`272`、`274` 不在树内且不是新根。首两次观察无该错误，第三次观察已在搜索页，第四次观察在音乐库歌单菜单；期间工具报告用户输入，因此不能把全部页面变化归于自动操作或假定精确点击顺序。

原生日志及四次观察位于会话 `outputs/IK-Music-页面统一-20261125/验收证据`。`Windows-新6a5c5ed原生成品-01.stderr.log` 是真实引擎错误；`Windows-原生成品01-全部逐动作.jsonl` 绑定本轮 PID、截图、辅助树和日志增量。辅助树的显示序号不是 Flutter Node2 的真实 ID，不能将其直接映射到日志错误编号。

本地完整06及两云均3368通过、18原条件跳过，只证明各自执行输入。新原生红门阻止发行，不能以全仓绿色覆盖成品失败。

## 已证实的覆盖缺口

`test/ik_semantics_tree_test.dart` 的 E16 是当前唯一启用 `workspacePageRefinements` 的完整新根 AX 门。它用 `tester.tap` 的默认触摸路径，未创建鼠标、悬停导航或遍历 Tooltip。旧 W-A11Y 迟启语义八组合以及 R10 鼠标完整回归保留原入口默认值，未启用本轮新正文框架。

因此“新正文框架＋鼠标悬停／离开＋迟启语义”的组合尚无正式门。该缺口已通过源码确认，但是否就是这次原生错误的原因，必须先由真实红门证明，不能凭推测撤掉现有 Overlay 或降低 AX 检查。

## 最小方案与验收门

本次属于既有缺陷修复与验收补强，不新增产品模块。方案一直接调整 Overlay 后观察界面，无法证明真实触发条件，不采用。方案二在现有正式套件中补可重复鼠标场景，先取原始失败批次和祖先关系，再只修对应新分支，采用此方案。

1. 复用现有真实 `VideoMusicApp` 装配、WindowsAppearance 和 `_WindowsAxDelta`，显式开启两个页面改版开关。先测试实际宽屏1920×1032、有歌、搜索导航悬停后迟启语义，再扩有歌／无歌与搜索导航／无悬停／发现导航／上一首八组合。
2. 鼠标通过同一 `PointerDeviceKind.mouse` 指针 move/down/up 操作，不用触摸tap替代。每次移动、按下、释放和退场以16毫秒逐帧提交到原完整AX校验；至少覆盖发现→搜索、搜索→发现和音乐库歌单菜单，30个真实数量的受控热词用完整状态而非一项样例。
3. 首轮仅增加测试，不改产品；若没有复现，保留实际绿色／边界并补受控网络返回或语义生命周期条件，不能制造断言失败冒充产品红门。
4. 失败后保留所有原始批次、节点、父子引用、控件标记和实际退出码。修复必须让同一门变绿，并保留 E16、旧W-A11Y和R10既有门。
5. 组件红绿仅证明确定性输入，最终仍需新同源成品的原生鼠标操作和完整独立stderr验证。

## 生产范围、调用方和回滚

当前仅修改既有正式测试和本票据，生产路径尚未修改。排查范围为 `IkDesktopWorkspace` 的新 `routeBody` 分支、主导航 Tooltip 及其根路由 Overlay；旧默认主框架、独立播放器退场和已有Slider隔离不因怀疑直接改动。若红门定位需要生产修复，须先在本票据补充确切原因、所有调用方及最小回滚后实施。

## E23 实际结果与后续受控场景

主任务已授权只在本正式文件继续补以下独立场景，不修改产品，不重跑无关旧组合，不把假设当根因：

1. E24：真实展开30个热词，逐项核对全部已显示；同一鼠标悬停搜索框、搜索导航、播放进度及音量滑块，在主区、内嵌下载和独立播放器之间往返。每帧仍走原 `_pumpAndCheck`。

3. E26：受控Future只控制完成时点，热词仍由真实 `_loadAlignedHotTerms` 接受，推荐仍由真实 `RecommendationsNotifier.loadLatestRecommendations` 接受。分别在内嵌下载及独立播放器显示期间返回30热词和三平台推荐；断言隐藏主区不泄漏可见语义、返回后内容与加载状态一致。此门验证迟到响应的结构变化，不调用公网、不冒称已验证任何平台实际服务。
