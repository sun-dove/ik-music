# IK Music 底部播放栏自适应微调票据

日期：2026-11-26。用户在约 1024 × 793 的 Windows 独立播放详情中指出底栏过宽松，希望底栏自适应。沿用第七份确认的排列：歌名和收藏相邻；播放与进度作为一个中央组；宽度足够时，两侧工具与中央组的整体中线对齐。

## 原因与方案

现有 `balancedLayout` 用到两处同为 24 的留白：每侧在工具所需宽度上另外加 24，中央组又和两侧各隔 24。默认字号下，右侧工具需要 324，进度组最小限制为 360；加上外边距，三组同层渲染实际需要 `40 + 48 + 2 × (324 + 24) + 360 = 1144` 逻辑像素。1024 窗口因此把歌曲和工具排在第一层，播放与较长的进度排在下方。

方案一：只降低固定窗口断点，但维持原宽度分配。会在足够容纳五个控制按钮和进度文字前强行横排，或在较宽正常窗口继续分层。

方案二：按当前字号工具的实际布局宽度留够两侧空间，只保留每侧一次间距，再计算中央组可用宽度。采用该方案。组间距为 16；标准字号时中央组最少 280，留给五个控制按钮及进度旁的时间文字，字号变大时相应提高最小宽度。标准字号、窗口宽 1024 时，中央组约 304 宽，进度自然缩短。中心最大宽维持 680；超宽窗口的三组作为整体居中，内容最大宽 1560，避免歌曲和工具贴到遥远的两端。无法容纳三组时继续使用原分层逻辑。

## 调用方与回滚

只调整 `lib/video_app/ik/ik_playback_bar.dart` 内现有 `balancedLayout` 布局分支。`lib/video_app/video_app.dart` 的 `_workspacePlaybackBar` 已在 Windows 快速版工作区和播放详情装配该分支；沿用独立详情 `inlineLyrics: false`、工作区原内联歌词和错误提示。两个构造器、`balancedLayout: false` 的默认布局、进度定位和播放行为不变。回滚仅撤销自适应分支的空间计算和横排容器；无数据或偏好迁移。
