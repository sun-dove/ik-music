# IK Music：智能均衡播放与全屏底栏

2026-11-26。现版基线为 0.6.2 预览 `3ee66d50f2e91f98927bb54d61de4a7832befafc`。播放策略仍是待确认的讨论稿。用户已另行明确要求「底栏……做自适应」，沿用已确认的中央播放键、进度长度、收藏位置及窄窗布局；全屏部分按下文独立实施并记录验收。两项互不依赖。

## 用户现在遇到什么

点一首歌，希望在能接受的等待里拿到好的音质，不想反复改设置、换源或点「继续尝试」。现版「优先最高可用」按 Hi-Res → 无损 → 高品质 → 标准排序；同一档会尝试所有合资格的来源，成功即停止。上游不提供某档、网络超时和音源初始化失败是不同问题。

已交付的 Windows 预览上，网易云《寒烟》在四次手动继续后经 HelloWorld 起播，时间从 1:17 推进到 4:01；详情里的「极高」是**请求档**，实际码率／格式未知。QQ 音乐《他不懂》首轮三个 Hi-Res 候选超时，第二轮结束累计试了 9 个、还有 53 个；不能断言余下的都失败了。本机另测同版沿用的 Windows LX 宿主，三次无网络冷实例取流的准备和收尾共用 1.21–1.66 秒。曾测到上游 503、504 或 404。把所有超时一律压回 2 秒，无法区分慢而可用的源和真正已失效的地址。

**现版的操作：**「设置 → 播放与音效 → 播放音质」选「高品质」，就是详情里写作「极高」的档位。它保留已有的自动切源设置；可在「设置 → 音源 → 播放策略」开「失败自动切换音源」并保存。固定高品质会跳过两个更高请求档，不会在本档失败后自动改请求标准；要恢复逐档尝试可选回「优先最高可用」。手动改音质可能让当前在线歌曲从原进度重新加载。下载音质单独设置。

## 可选方案

| 做法 | 用户得到什么 | 代价与决定 |
| --- | --- | --- |
| 保持现版，固定高品质或标准 | 今天就能用，少走一些档位 | 档位不合适时要手动改；不再缩原时限。保留这个选择。 |
| 新增「智能均衡」，只改变被选中模式的尝试顺序 | 同一首歌重播先试成功组合；初听先给好音质机会，随后尽早试可播保底。一次只加载一个媒体 | 可能先播到高品质而没有穷尽所有 Hi-Res。**推荐首版。** |
| 同时解析两路，第一条可加载就用 | 在一个源很慢、另一个很快时可能更快 | 现有会话共用游标、取消令牌及音频后端，官方回包信息也按歌曲共享；Android 宿主还有资源上限。需要独立取消、质量证据归属和唯一播放者。暂不采用。 |

## 推荐的播放规则

1. 只在用户选了「智能均衡」后启用。既有「优先最高可用」及各固定档保持原含义。自动切源关闭时，仍按当前规则只在官方和首个已启用的脚本范围内尝试；不会偷偷打开音源。用户显式修改首选或顺序后，旧命中不越过新选择。账号切换、源移除、停用或脚本更新后不用旧命中。
2. 用平台和稳定歌曲 ID 找**这首歌**最近真正播过的「源＋请求档」；先在当前设置允许的优先组内尝试它。没有本曲记录时，同档同优先级下先看这个平台近期播成功的源；有多个时比较它们各自从开始尝试**这一个源**到有效播放进度的耗时，避免把排在它前面的源消耗的时间算给它。取最近最多 3 次有效记录的中位数，同分保留原顺序，无记录的保留原相对次序。记录限本次应用进程、最多 128 条，不需要把听歌历史发给服务端；拟定高品质及以上有效 30 分钟，标准保底有效 5 分钟。到期重新给高档机会。这些是可调整的设计值，不是现版实测性能。
3. 无本曲命中时，第一项优先选同平台近期能播的 Hi-Res／无损；两个都没证据时先给无损一次机会，所选层没有合资格候选则顺延。接着试一个高品质候选；仍不成功就试一个标准候选，不必先试完每个源的 Hi-Res。即时失败立即推进，不人为凑满秒数。还有时间但三项均未起播，则按原高到低顺序继续未试过的候选。某档没有可用候选就跳过，一轮总预算到期仍停止，不保证每档一定来得及完成。每个（源、请求档）只试一次，未试候选留作「继续尝试」。在同档内按用户设置区分官方／脚本先后与显式首选；同一优先组才用历史打破平局。
4. 仍保留解析最多 5 秒、媒体加载最多 5 秒、同一轮合计 15 秒的边界；不是每首必等 15 秒。第一条真正能播的流开始播放后就结束本次寻找，不后台追高、不切掉已响的歌。切歌、暂停或取消后的迟到结果不计成功。拿到 URL、脚本自检通过、未开始播放或只有旧歌曲的进度，都不作为本曲命中。
5. 用户只在现有「播放音质」菜单多见一个选项，不增加秒数、优先级或并发数设置。成功详情区分「请求高品质」与「实际码率／格式」；音源没有回传可靠证据时显示「未知」。还有候选才显示「继续尝试」，耗尽了才提示所有合资格候选均失败。下载、离线文件、本地播放和对私有源的权限规则不变。

## 接口、调用方与回滚

| 接入点 | 本次拟增加的能力和受影响的调用方 |
| --- | --- |
| 偏好与入口 | 在 `IkManagedMusicPreferences` 旁添加可选的 IK 播放策略读取／保存入口；只在显式选中时写独立可选键。旧配置没有该键时精确走原策略。音质菜单及音源管理的最高档开关必须读到同一状态；显式选固定／最高或更改最高开关时，在既有受管串行写入内清除智能模式。只改自动切源或首选不退出智能模式。设置保存失败保留旧值和界面选择。针对 `IkSettingsWorkspace._quality`、`VideoMusicApp` 下的统一音质入口（含详情）及 `SourceManagerPage` 检查，未装配此功能的旧调用保持不变。 |
| 候选排序 | 新增只服务于播放的规划器，输入当前合资格列表、用户优先顺序、平台／曲目、近期成功及本轮状态；输出下一个未尝试的候选。范围来自 V3 播放候选和它的能力排除规则（智能模式取完整四档），不能从只有一个固定档的列表凭空调序。维持原 `buildSourceCandidatesV3`、`sourceExclusionsV3`、`SourceSession.next()` 和所有下载调用契约。IK 入口 `main_video.dart` 经 `IkCatalogPlayerNotifier`、`ExpandedSourcePlayerNotifier` 至 `MultiSourceVideoPlayerNotifier._createSession/_advance` 可选装配，无注入即走旧路径。 |
| 起播证据 | 在已有的媒体成功和代次校验之后，可选观察同一平台、同一曲目、同一媒体代次的第一次正向播放进度，排除拖动、恢复进度产生的跳点；这时才记入成功表。条目仅含歌曲／源标识、请求档、来源版本或配置代次、时间及本候选起播耗时；不存 URL、账号、凭据、脚本、歌词。缺记录不影响播放。`SourceCheckRecord` 是脚本自检，不能代用。`MultiSourceService`／`PreparedSourceRouter` 保持串行。首版不改平台 API、不并发调用 `next()` 或 `setUrl()`。 |
| 回滚 | UI 选回原模式立即恢复以后的原排序；代码回滚则移除 IK 入口的可选装配。旧程序忽略新键；旧音质、切源开关和下载偏好不迁移。移除全屏宽度覆盖即可单独回滚下述样式。 |

## 全屏底栏

截图为 1920 × 1032。全屏时背景仍铺满底部；问题是等宽侧栏把空白留在歌曲／工具与中央播放区之间。方案一是把固定内容上限从 1560 改到 1424：能收紧此截图，但碰到短歌、独立详情或大字体仍按一个尺寸分配。用户追问能不能自适应，采用方案二：用**底栏本身的可用宽度、字号和组内真实内容**围绕播放区排布。标题与心相邻，工作区的当前歌词和失败操作互相替代，右侧工具内间隔不变。独立详情不重复底栏歌词。

中央沿用既有长度和换行条件。内侧可用宽度记作 A，字号决定右侧工具占宽 R（默认 324）；中央宽 C = 限制到 0–680 的 `A − 2 × (R + 16)`。C 小于当前字号可容纳的最小中央宽就使用原分层，否则每侧可用 H = (A − C) / 2，内侧组距 G = `clamp(16 + 0.05 × max(0, H − R − 16), 16, 28)`。左组自然宽，靠中央左边收尾；右组靠中央右边起排。多余空间在组外，不让三组越拉越散。歌词保留稳定宽度，不能随着每行歌词、每秒进度移动歌名、播放键或工具。在容不下长歌名、歌词或提示的槽内沿用原省略、换行、点击和滚动。单层垂直对齐的是「播放键＋进度」整体。

默认字号、底栏两边各 20：1024／1280／1440／1920 宽的中央区分别为 304／560／680／680，组距为 16／16／17／28；这些是逻辑像素，C 包含时间文字。截图的原有可见间隙约 108 和 131，新排布的示意约 32 和 43（按钮内部自带空隙，不能拿视觉间隙当布局参数）。左右位置按各自内容收合，不要求等量位移。

只在 IK Windows 的快版工作区、内嵌详情壳和独立播放详情，由 `video_app.dart` 的 `_workspacePlaybackBar` 给现有对齐播放栏显式启用可选 `contentAdaptive`。既有构造、缺省、未开启此项的其他使用者、Android 及旧布局均保持。回滚只需不注入该选项；无数据或偏好迁移。这是反馈指明的局部样式修正，不改媒体管线、设置卡、原生界面或其他页面。用户对换源策略的确认不作为底栏开工条件。

## 场景与可执行验收门（尚未实施）

先给真实的 Flutter 组件、候选规划器和可控时钟／媒体控制器写门，在现版上确认针对新行为的断言为红；再按「设置与候选 → 成功反馈 → 两端接入」实现。底栏独立做 1920 几何首红，再调整样式。本票据不是通过回执。

| 真实场景 | 体验与功能门 |
| --- | --- |
| 首听、第一条无损确实可播 | 选智能均衡后首次正向进度出现；只调用一条来源，不再探测或为高档重载。不能只断言找到了 URL。 |
| 多个 Hi-Res 源很慢，高品质或标准可播 | 可控时钟构造两组：慢高档＋真高品质、慢高档＋只有标准；与旧原序比较首次起播时间。检查低档在整轮仍有时间时提前入选；明确失败立即推进；保留未试组合且不重复。另测解析成功但加载失败以及整轮到期。 |
| 同曲重播，或同名不同平台／歌手 | 热命中只属于平台与歌曲 ID；重播先试成功组合；下一首不沿用上一首的实际码率。失效、仅拿到 URL、点击后取消、播放失败都不写成功。标准历史到期后重新试高档。 |
| 用户切歌、调源、关闭自动切源 | 不加载迟到的旧歌，不开禁用源；改首选／下线／换账号后旧命中失效。正常在播时音源管理更新按原平台规则；切为固定音质维持既有显式换档行为。 |
| 旧偏好、下载与失败文案 | 无新键和选择旧模式时，原顺序、已启用范围和下载候选严格相同；设置写盘失败界面回到原值。区分还有候选／确已耗尽；不同证据决定是否显示实际码率。 |
| 全屏工作区及独立详情，含失败提示 | 1920 默认字号，三组同层；播放组与按钮的水平中心不偏离 1 个逻辑像素，中央宽 680。最后可用的左侧内容紧邻中央，首个右控件靠近中央；不能以歌名外层撑满的空盒代替肉眼可见的心、提示或歌词。标题／心／继续或重试／详情／右工具能点击，长歌名和不同歌词不推走中央或遮住操作。实际字形的空隙允许与示意不同。 |
| 还原窗口和放大字号 | 测 1920、1440、1280、1024 普通，800 窄窗、1024 的 150% 字号；测拖窗和无歌曲／长歌名／错误状态。1024 默认维持同排和原进度宽，空间不足自动分层。覆盖详情与工作区，确认收紧的几何门在旧版确实失败。 |

成品比较按两端分别记录「点击到第一段持续前进的播放进度」、首轮成功首数／总首数、所请求与已确认的实际音质，同时记录未能起播的样本。冷启动和同曲重播分开，使用相同曲目、源集合及网络条件，交替顺序；报告成功样本的中位数和较慢的 90 分位，失败与未测范围另列。若同一条件下首轮成功率下降，或高档可用场景被普遍降档，不能仅凭成功样本变快判为通过。没有成品数据之前不承诺「一两秒」或「每首都播到最高」。
