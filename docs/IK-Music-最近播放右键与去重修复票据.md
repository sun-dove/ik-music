# IK Music 最近播放右键与去重修复票据

日期：2026-11-26。状态：用户要求继续修正，源码实施；本轮仍暂停测试、检查、构建和运行验证。

## 问题与目标

新版“最近播放”逐条显示收听明细，同一首歌会反复占据多行，鼠标右键也没有歌曲操作。用户需要按歌曲浏览近期收听，并能明确地“从最近播放移除”。本轮属于既有页面的小功能增强与缺陷修复，沿用已确认的新版表格和现代菜单，不新增页面或存储模型。

选择只在新版视图聚合，保留原始收听明细。备选方案是修改历史录入算法或复用 `Song.dedupeKey`，但前者会改变已有统计语义，后者会剥除 Live、重制、feat 等版本并只保留主歌手，不能满足此次准确分组。新增 `contextActions` 可选开关，默认 false；新版 Windows 入口显式启用。

## 场景、接口与确定性规则

1. 最近播放按时间降序投影。同一 `(platform,id)` 始终归入它最近一次元信息对应的组；不同身份只有在完整歌名及完整非空歌手集合一致时才合并。标准化仅收敛空白、转小写、对歌手去重排序，不剥除版本、标点或合作歌手。未知、缺失歌手或空标题回退精确身份，不跨平台猜测。
2. 每组只展示最近一次，计数、时间、播放列表和当前播放高亮来自同一投影。旧历史数据、`fingerprint`、`dedupeKey` 与录入的十秒合并规则不变。
3. 右键在鼠标位置展开现代歌曲菜单，更多按钮打开同一个菜单。复用既有下一首、歌单、下载、喜欢和分享动作，附加“从最近播放移除”。
4. 新 `HistoryNotifier.removeRecentSongsHistory(Iterable<Song>)` 接收所见组内的全部精确歌曲身份；新 DAO 同名方法在事务内只删除这些身份的 `ListeningHistory`。不使用名称模糊删除，不删除 `Songs`、文件、收藏、歌单、当前队列、`PlayEvents` 或 `DailyStats`。
5. 数据库成功后才移除内存行；失败保留列表并显示“移除失败，请重试”。新增历史写入队列按调用顺序收束原本在途的录入与移除，取消该组尚未执行的三秒录入，并使删除前／删除期间的旧历史读取失效，避免旧结果覆盖新列表。
6. 统计回填原方法在找不到历史时会插入记录，属于本次必须覆盖的额外调用方。新增 DAO `recordRecentListen`、`backfillRecentListenedDuration` 包装与仅内存的已移除身份集合，串行处理新版运行时的历史写入。删除成功后，当前播放继续产生的时长回填不重建历史；下一次显式录入成功后解除该身份屏障。旧 DAO 两个方法的签名和实现保留，未删除身份的结果保持。

上述规则是确定性身份与字段比较，不调用语义分类或 Jev。

原历史页面、智能歌单读取、备份与设置刷新继续使用现有 provider。它们会看到用户主动删除后的历史数据，但不采用新版页面的视图聚合。既有 DAO 直接调用方继续使用原方法，统计来源表不变。此生产接线的必要原因和回滚在本票据记录，用户已明确要求移除该条记录与最近播放不重复，无需新增权限确认。

## 实施顺序与回滚

先记录以上场景和待验收门，再新增视图投影、DAO 方法与删除保护，最后接现代菜单和新版入口。当前阶段只修改源码，不执行任何用户数据删除。

回滚时关闭入口 `contextActions`，恢复 history provider 的录入与 stats provider 的回填到原 DAO 方法，并移除新增在途保护调用；新 DAO 和文案可以暂存为未调用代码。无 schema、字段或数据格式迁移。用户已明确执行成功的移除属于真实操作，不生成隐式备份，不通过回滚源码恢复历史。

## 待验收门（尚未执行）

| 场景 | 功能门 | 体验门 |
| --- | --- | --- |
| 同一精确身份重复播放、元信息变化 | 同身份只归最新元信息组，原始历史明细不被合并删除 | 最近播放仅一行、最新时间置顶，条数和点击播放顺序一致 |
| 跨平台同歌、同歌名不同歌手、版本和多歌手 | 完整字段相同才合并；歌手顺序不影响；缺失歌手回退身份；Live 和原版分开 | 只出现预期合并，当前播放高亮至多一行 |
| 更多按钮与鼠标右键 | 两者调用同一歌曲动作入口，附加操作只收组内精确身份 | 鼠标位置菜单和按钮锚点菜单均能看到“从最近播放移除” |
| 多身份组移除成功 | 事务删除组内全部身份历史；其他表／曲目不动 | 数据库成功后行消失、计数同步、显示成功反馈 |

| 删除当前播放，再主动播放该曲 | 当前统计继续记录；新的成功录入解除身份屏障 | 不暂停当前播放；后来主动播放能再次出现在最近播放 |
| 缺省兼容 | 不传 `contextActions` 仍逐条展示；旧 DAO 公开方法和规则保留 | 原页面操作回调及已有入口布局保持 |

本轮这些门仍是待验收条件，不能表述为通过。未创建测试、缓存、临时数据库或验证产物；未操作用户播放进程、窗口或真实数据库；不提交代码。

## 本轮源码结果

以上视图、菜单和数据方法已落盘。新版页面只订阅当前歌曲变化，不因播放进度每次更新而重新对全量历史排序。右键和更多菜单使用页面的反馈上下文并传入鼠标／按钮全局锚点，移除行后成功提示仍可显示。分组内部保存确切平台与歌曲 ID；跨平台聚合组的删除会遍历所有成员身份。

DAO 的移除屏障只存在当前数据库实例内，成功删除后才加入，失败不加入；下一次成功的显式历史录入解除。当前播放的统计仍写入原统计表。重启不保留旧定时器或在途回填，因此不新增持久化屏障、表或字段。主任务已在快速 Windows 体验入口显式开启 `contextActions`，旧入口可选参数仍为 false。

未运行测试、静态检查、格式检查、构建、GUI 或实时网络探测，未实际删除任何用户历史。
