# IK Music 桌面重设计与整合方案

日期：2026-11-20。状态：用户已审阅并明确授权“继续改版、打包、发布”，方案B及本稿审阅修订进入实施；临时垃圾按用户要求留待后续统一处理。HTML不等同于已安装的Flutter成品。用户要求IK Music名称、减少弹窗、明确音乐库/设置、最近播放、3D环绕、桌面歌词、自动整合指定音源，以及安装目录迁移和控制包体。本要求覆盖旧0.6.0候选的交付安排，最终发布必须使用新实现验收后的包。

## 一、问题与目标

当前版本把移动端底部弹层直接铺到大屏幕；一页集中账号、曲库数量、音源、质量、外观和个人工具，分组与职责不清。“我的音乐”和“我的”同属一级导航，但后者实际上是设置；宽窗还固定占用 280px 展示待播队列。设置项文字小、上下距离大，用户需要反复开关弹层才能修改一个简单值。

目标是形成一套紧凑、清楚且适合鼠标操作的桌面界面：音乐内容有明确入口；设置在页面内操作并即时反馈；底部播放栏持续可达；功能只有原生实际生效才显示成功。名称与图标一致，旧数据和安装升级保持兼容。界面完成和音频实际能力是两套验收，不能用可点击的演示开关替代真实 DSP。

## 二、两个方案与选择

| 方案 | 改动 | 优点 | 不足 |
| --- | --- | --- | --- |
| A：现页轻改 | 修改“我的”标题、收起右队列、调整颜色/圆角；仍复用当前长页与弹层 | 代码少，短期快 | 功能层次仍乱；桌面操作仍需要反复弹层，难以满足本次反馈 |
| B：独立桌面工作区与分区设置（推荐） | 在既有独立 Router 下新增桌面壳、设置分区与行内编辑；复用已有 providers、歌词原生窗、搜索/收藏/下载契约 | 职责清楚，可减少大部分简单弹层；不牺牲旧功能；兼容边界明确 | 需新增桌面组件及路由装配门，重验窗口尺寸和状态保持 |

采用 B 的审阅稿：`design/ik-music-desktop-redesign.html`。亮色使用中性灰白、青绿操作色与较轻的分隔；深色保持同一布局。圆角只用于独立功能区域，避免大面积空白和每一行都是大卡片。保持系统中文字体，正文 13–15px、辅助 12px，不随包引入体积大且无分发依据的字体。

Jev 已实际调用，模型 `jev-1.14.0`：简单设置行内、曲库与设置分离均置信度 1.00，页内外观预览 0.98；这些仅作方案复核，具体界面按用户选择确定。3D 技术方案的置信度为 0.61，必须由原型验证，不能当作已经可行的保证。

## 三、名称、导航与信息布局

用户可见名称统一 **IK Music**：窗口标题、左上 logo 旁、桌面/开始菜单快捷方式、Android 应用名及关于页。安装文件夹使用小写连字符 **ik-music**。内部包名、Android 签名、Windows AppId、CompanyName/ProductName、EXE 与存储目录保持，不用显示名改变去强行迁移账号数据。

一级导航为：

1. **发现**：继续播放、推荐、新歌、榜单。区块有数量上限时明确“最近 N 首/精选 N 首”，并提供查看全部。
2. **搜索**：一次输入，多来源独立加载/失败/分页/筛选。
3. **音乐库**：喜欢的音乐、歌单、本地音乐、下载、智能歌单。平台是来源筛选；登录入口用单行提示，不把三份账号卡堆成整页空白。
4. **最近播放**：真正播放历史，按时间排列；从这里进入听歌统计。它不是当前队列的改名，不把尚未播放的曲目混入历史。
5. **设置**：在侧栏底部固定入口，与音乐内容分开。

宽窗取消右侧常驻队列。播放引擎仍需要内部队列来确定下一首；底部保留“接下来播放”按钮，点击后才打开窄抽屉，再次点击/Esc/关闭即可收起。最近播放有独立完整页面，首页只展示简短预览。原 `/queue` 路由仍兼容。

底部播放栏包含曲目、喜欢、前后首、播放/暂停、循环、进度、音量、**词**、音效、待播列表。主区与所有详情页共用同一播放状态，切页不失去控制。播放失败显示短原因与可重试操作，不能让静态封面表示正在播放。

## 四、设置分区与弹窗规则

| 分区 | 主要内容 | 交互 |
| --- | --- | --- |
| 播放与音效 | 播放音质、淡入淡出、均衡器、3D 环绕、睡眠定时 | 行内下拉、开关、滑块；显示保存中/生效/失败，不每次弹成功框 |
| 外观 | 主题、字体、背景、关闭窗口行为 | 主题三选一；字体与背景页内预览、应用/取消；关闭行为直接二选一 |
| 桌面歌词 | 显示、锁定、字号、正文色、高亮色、当前预览 | 行内编辑；底栏快捷开关与这里保持同步 |
| 音源 | 内置目录、准备进度、逐项状态、启停、优先级、更新与高级导入 | 独立页面管理；默认不用粘贴链接，失败有原因与单项重试 |
| 下载与缓存 | 下载音质、保存目录、容量和已有下载策略 | 直接修改，目录使用系统选择；任务列表在音乐库 |
| 账号 | 三平台登录、同步、失效、退出 | 每平台紧凑一行；登录转已有完整页面；不自动代登录 |
| 备份与恢复 | 导出、选择文件、内容摘要、恢复点、导入结果 | 先页内检查，再显式确认；取消不写数据 |

保留必要的系统选文件/目录、权限和破坏性操作确认。普通主题、音质、关闭行为、音效开关不再用底部大弹层。Windows 歌曲“更多”使用锚定菜单；需要复杂输入的操作用定宽居中窗口或完整页面，主次动作和关闭入口一致。移动端保持适合触摸的响应式布局，不能硬压桌面两栏。

界面状态顺序：用户选择→行内应用中→实际成功再显示当前值。失败时恢复旧值并在该行显示原因/重试；不会出现“已应用”但后端没生效。背景和字体保留取消/预览生命周期。

### 审阅修订：下拉与侧栏文案（2026-11-20）

用户指出来源下拉仍显示 Windows 原生蓝色列表，且侧栏底部文案换行凌乱。此次属于已授权的设计稿样式与小交互修订，只修改 HTML 审阅稿，不涉及已安装程序或公开接口。保留账号入口，将文案简化为“连接账号 / 同步收藏”，每行完整显示；移动窄屏改成与设置并列的两个带可访问名称的图标按钮。

原生下拉虽代码少，但展开部分无法稳定随应用主题呈现；采用共用的锚定列表，统一来源、音质、均衡器预设、定时、字体、下载任务与缓存容量。圆角、边框、阴影和歌曲更多菜单一致，选中项用青绿底与勾选标记。菜单挂在页面浮层，空间不足时向上展开，内容超高则内部滚动。

本次先检查修改前真实页面：来源仍是原生 `select`，不存在统一列表和账号入口，以下场景尚未通过。修订完成后使用真实浏览器重验，不新增临时测试文件。

| 门 | 真实场景与通过条件 |
| --- | --- |
| D01 | 在音乐库展开来源：无原生蓝色列表；当前值和勾选对应；选择网易云后只出现两首对应演示曲目，重新进入仍保留筛选 |
| D02 | 七处设置下拉及搜索来源共用样式，切页/主题重绘后保留当前选择；选择不会弹成功框 |
| D03 | Enter/空格打开与确认，方向键/Home/End 移动，Escape 取消并恢复焦点，Tab 正常到下个控件，点击外部关闭 |
| D04 | 浅色/深色、1440/1200/900/720/390/320 宽度及视口底部展开不裁切；滚动/缩放后关闭，菜单内部滚动正常 |
| D05 | 桌面账号两行均不折行；320/390 宽下账号/设置图标各至少 44px，与品牌、主导航不重叠；点击账号进入账号设置 |
| D06 | 来源筛选后歌曲菜单与完整播放器仍指向同一首，返回保留筛选与滚动位置；同时只显示一个选择/歌曲菜单 |

## 六、桌面歌词的具体接入

现 Windows 原生歌词窗口已经实现显示、隐藏、置顶、当前/下一句、翻译、高亮、字号/颜色、拖动/缩放与锁定；成品已实际开关验证。新需求的重点是让用户找得到，并保证状态真实。

新增 ik 共用歌词动作，复用现 `IkFloatingLyricsPage._toggle` 的严格顺序：检查能力→show/hide 成功→保存状态→同步歌词。底栏两处装配和完整播放器调用同一动作，不能直接使用旧乐观 `toggleEnabled()`。失败显示原因，开关不假亮；用户关闭原生窗口时按钮同步关闭。

当前 Windows 字体家族固定微软雅黑 UI，锁定只禁拖动/缩放，**没有鼠标穿透**；现设置中的描边/阴影滑块没有被 Windows 通道消费。新界面先仅展示真实有效项；若要加入字体族、描边、阴影、穿透或位置记忆，必须另写原生双路门后接入。不能沿用“可调”控件但实际没有效果。

## 七、3D 环绕与音效真值

技术证据、两方案、数据结构与信号门见 [3D 音效技术调研](IK-Music-3D音效技术调研.md)。当前裁剪版 libmpv 实测缺少八种空间滤镜；设置字符串成功并不能证明图初始化成功。现 EQ 对一种 s16 输入也出现缺重采样后自动禁用的事实，需要一并补正确的生效反馈和信号门。

推荐先验证小型 HRTF DSP 原型：Windows 接入同一解码 DLL 的定制滤镜，Android 使用受控 PCM 处理适配；不再捆绑另一套完整 FFmpeg。目标新增每 ABI/Windows DLL 的代码及资产不超过 2 MiB，超限先重新评估。HRTF 表的初步计算为两种采样率合计 288 KiB，这不是最终成品大小。必须获得可分发的真实 HRTF 数据并验证许可。

产品状态为关闭、待播放、应用中、实际生效、不支持、失败已恢复。只有原生节点确实初始化并处理帧才进入生效；固定信号门验证真实处理，切歌/seek/音质/均衡器/设备切换不得相互覆盖。用户没有要求 Dolby/Atmos、头部追踪或还原不存在的录音对象，不把这些扩进本版。

## 八、内置音源与安装减包

内置音源方案见 [内置音源接入设计](IK-Music-内置音源接入设计.md)。推荐随包只含固定目录与哈希，首次启动自动下载校验，用户无需逐项粘贴。上游当前固定提交与历史 20 源矩阵相同，不重复已完成调研。目录始终可见，下载/初始化/歌曲播放分别显示结果；离线可启动，准备失败不阻塞其他功能。更新不恢复用户禁用/删除，也不覆盖已有源与音质策略；有脚本限制的项目保留限制。聚合仓库无统一 LICENSE，不把 20 个脚本当作统一获准随包分发。

安装目标本机为 `D:/Applications/ik-music`，普通新用户默认本地 Programs 下的 `ik-music`。安全迁移和真实包体清单见 [安装迁移与包体方案](IK-Music-安装迁移与包体方案.md)。当前安装器 18.842 MiB，ARM64 包 33.884 MiB；87.75% 的 Windows 展开体积是 Flutter、解码器和 AOT，不能直接删。

先在隔离安装场景验证新包、旧卸载/新安装登记和数据保持，再迁移本机；旧卸载器必须在同 AppId 的新安装之前运行，不能先新装再运行旧卸载器。新程序验证成功后仅清理有归属记录的旧残留，未知文件保留并报告。账号/收藏等原 Roaming 数据继续复用。

减包先检查独立构建实际无用的 Android 扫码依赖，其每 ABI native 库约 2.8–5.5 MB；不从 APK 手工删库。必要 DLL、LX 宿主、数据库及许可保留；新3D不捆绑 216 MiB 的完整 ffmpeg。最终包体以重建后的精确字节比较，不承诺未经构建的缩减量。

## 九、新组件、状态与生产接入票据

推荐新增 `IkDesktopWorkspace`、`IkSettingsWorkspace`、`IkInlineSettingRow`、`IkPlaybackBar`，仅独立桌面新布局启用；旧构造缺省保持。不会为视觉重构更改数据库、播放器算法或公开旧方法。

实施兼容开关为 `VideoMusicApp.workspace=false`（新增可选参数）；`main_video`显式设为true。旧`redesign`四区和旧`IkShell`仍按原默认执行，新的五区与七项设置仅在workspace中装配。路由新增可选设置builder与设置分区路径，旧音效/歌词路径继续有效。旧内容页与Provider不重新实现，新的菜单、底栏、歌词严格动作由独立组件共用。新增正式门先在workspace=false及现有旧行为上取得可观察红态，再接线变绿。

```text
IkWorkspaceSection = discovery | search | library | recent | settings
IkSettingsSection = audio | appearance | lyrics | sources | downloads | accounts | backup
InlineEditState<T> = { savedValue, draftValue?, phase, error?, retryable }
phase = ready | preview | applying | failed
```

| 接入点 | 受影响调用方 | 回滚 |
| --- | --- | --- |
| `VideoMusicApp/_VideoHome` 独立装配 | 新主壳、设置页、主区与详情底栏 | 停用新桌面布局，回原独立四区；存储不删除 |
| `createIkRouter` | 最近播放、统计、设置分区路由与返回 | 保留旧路径别名；移除新builder可回退 |
| `WindowsAppearance`/质量/音效 providers | 新行内控件调用已有方法，通知刷新 | 取消新控件调用，保留原页与方法 |
| `VideoMiniPlayer/WindowsPlayerPage` | 新增可选歌词入口及状态 | 不传参数保持旧行为 |
| `main_video` 音源准备与空间运行时 | 仅新能力显式装配 | 停用独立协调器，已保存用户配置不删除 |
| 版本/显示名/安装器 | IK Music 显示、新文件夹、快捷方式目标迁移 | 更高build恢复旧显示；数据目录保持；安装回滚按附件 |

现有三项收尾修复和 build 11 版本生成文件保留。新增设计批准后在这些已绿成果上继续，不重复设计旧功能、不把现有候选包当作新设计包分发。

## 十、真实场景与验收门

所有新增正式功能门先运行成红，之后才实现。复杂原生音效先用独立原型证明可行，产品状态门与音频信号门分别通过；不靠截图或测试数量替代。
