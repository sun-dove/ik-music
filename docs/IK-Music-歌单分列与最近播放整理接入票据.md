# IK Music 歌单分列与最近播放整理接入票据

日期：2026-11-26。用户在第四份预览制作过程中追加两组截图：歌单歌曲信息挤在左侧，中间大片空白且没有鼠标右键；最近播放每次播放都增加重复条目，同名不同歌手应保持独立。以下为这批已明确要求的列表体验与小操作修正。

## 目标与方案

歌单详情宽屏把歌曲、歌手、专辑、时长、操作分列，歌手放到用户圈出的区域；窄屏保留合并信息，下载、播放全部、批量与更多动作保持。方案A继续ListTile仅把subtitle换位置，难保证多列对齐；方案B使用已有工作区表格风格并新增可选桌面分支，采用B。现旧页面调用默认不变。

右键菜单在鼠标位置打开，与更多菜单同一组歌曲动作；最近播放追加“从最近播放移除”。不使用旧底部弹层，不把从历史移除标成删除音乐文件。添加新的菜单入口／扩展动作描述，不删除或改名旧公开方法。

最近播放原始记录为每次播放事件，页面直接展示明细才导致同歌重复。方案A删旧记录或改变历史写入算法，会影响统计；方案B仅新页面按歌曲分组，保留最近一次显示与原统计明细，采用B。规则为相同平台ID同曲优先，跨来源完整歌名＋完整歌手集合在大小写／空白标准化后相同可归一；歌手不同、完整歌名中的Live／翻唱／版本标记不同保持独立。歌手缺失时按平台ID区分，避免未知作者的同名曲被合并。旧 `Song.dedupeKey` 会剥离版本，不复用或修改它。

排序和时间用每组最近一次，数量与点击播放队列使用同一分组列表，不能只改画面导致点击错曲。移除时仅删除选中组对应的确切平台ID历史，成功后更新；失败保留条目并显示原因。不删除歌曲表、收藏、文件、当前播放队列或听歌统计表；只有用户主动选择移除才执行写操作。

## 接线与影响范围

- `PlaylistDetailPage` 新可选 `desktopTable=false`，只有 `createIkRefinedWorkspaceRouter` 的Windows歌单详情显式开启。旧路由工厂签名和其它页面默认保留。
- `IkRecentPage` 新可选交互分支，只在Windows快速入口开启；聚合投影和历史删除新增方法保留旧接口与默认记录行为。
- 歌曲菜单新增支持鼠标位置及额外动作的入口，复用原动作执行，不改变现有调用方签名。
- 原有持续记录／异步读取必须避免把刚成功移除的旧记录立即回写；必要的新增状态仅服务此新操作，现record接口签名保持。

本轮不对用户数据实际执行删除，只交付菜单与操作能力。回滚关闭新歌单／最近播放入口开关，旧UI和历史明细立即恢复；新方法无调用则无影响，用户文件不迁移。用户最新要求已明确授权上述列表修正，无需另行确认。

## 先记录验收场景

| 场景 | 体验门 | 功能门 |
| --- | --- | --- |
| 宽／窄歌单 | 多列对齐、歌手可读、无大面积无效空白，操作仍可达 | 只新分支启用，歌曲顺序和播放索引不变 |
| 歌单右键／更多 | 同一现代菜单与可用动作，点外／Esc关闭 | 右键位置正确，不因菜单开启动歌；旧菜单默认不变 |
| 同一首反复播放 | 只有一行，最新时间与位置更新 | 原明细保留、去重数量和播放队列一致 |
| 同名不同歌手／版本 | 分开显示 | 不仅按标题合并，不剥离版本标记，未知歌手回退精确身份 |
| 最近播放移除成功 | 所选歌曲组消失，其他条目保留 | 只该组精确历史身份删除，旧读取／待写不会立即复活 |
| 移除失败或连续操作 | 失败可见且可重试，不假成功 | 不丢当前条目／用户文件，不执行双写或越界删除 |

按用户优先快版指令，本轮暂不运行全仓、静态分析、格式检查或GUI验收；不把新增规格称为绿色。源码收口后与底栏居中、网易真实图片请求修正一起编译第四份预览。
