# IK Music：歌单层级、搜索密度与每日30首追加设计

日期：2026-11-22。源码基线：`95ea99ae795da855cb81dcf31713f7f19dbb7dd0`。本文件依据用户新发的两张实际截图及“太多了”“各平台的每日推荐30首”追加要求，区分可以直接修复的已有界面问题与需要讨论确认的新平台能力。

## 一、问题与目标

音乐库已经采用五分类同壳，但嵌入的歌单页仍带自己的“我的歌单”标题和本机／网易／QQ／酷狗四标签，与外层“我的歌单”重复。搜索页直接遍历全部真实热词，30词占据四行；推荐精选又纵向堆三个平台，首屏层级过多。

这两项属于用户已经指出并要求处理的界面缺陷／样式小增强，沿用已确认的同壳、来源筛选和简洁搜索设计，在本票据中写明必要接入后实施。旧公开构造、原独立歌单页和默认搜索行为保留；新增呈现参数可选、默认关闭，不修改数据库、登录、歌曲播放或下载算法。

三平台**真实个人每日30首**尚未完成。此前网易每日歌曲、QQ私享页面和酷狗首页回退只能证明不同的已有能力。本次将继续核查真实个人接口；新增外部协议属于复杂功能，必须先完成本设计、向用户讨论确认，再编码。图标、品牌、历史包和已完成的九附件核验不重复。

## 二、已有界面的两个方案

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| A：保留双层标签，只改间距 | 去掉歌单页一个标题；热词缩小字号，仍展示全部 | 仍有两层相似导航和四行热词，不能充分解决用户说的“太多” |
| B：分类固定、来源收为选择器、搜索分块（采用） | 保留音乐库五分类；歌单页用一个“本机歌单／网易云／QQ／酷狗”锚定选择器，同行保留刷新和新建；搜索默认前10个真实热词，可展开／收起；推荐精选按一个平台切换 | 视觉层级减少，全部能力和真实热词仍可达；不以更小字号挤空间 |

歌单来源选择器使用已有 `IkSelect`。保留原 `TabController` 和 `TabBarView` 的数据、选中状态和生命周期；仅新命名紧凑构造隐藏旧标题与 `TabBar`，选择菜单同步到原控制器。本机歌单名称与“本地音乐”区分，避免让用户误以为是音频扫描入口。新建、导入、刷新、详情返回、删除和导出沿用原操作。

搜索空态将来源下拉与标题尽可能放在同一行。热词来源用小字显示，真实列表按原顺序默认展示10项，点击“展开全部”才能查看剩余项，收起不重新请求。推荐精选保留查看全部入口与真实来源说明，只显示当前选中的一个平台；网络失败、空结果和重试不因简化消失。搜索的“全部来源”只控制正式查询结果，推荐平台选择具有明确独立标签。

## 五、真实个人每日30首方案（方案B已确认，实施记录见第十二节）

| 方案 | 接入方式 | 取舍 |
| --- | --- | --- |
| A：把现有推荐统一改名并取30 | 网易日歌、QQ榜单和酷狗首页混用现有provider，界面统一称每日30 | 实现少，但公开回退不等于个人推荐，不满足用户要求，不采用 |
| B：新增严格的个人日推入口（推荐） | 使用各平台现有有效会话，请求真实个人接口；新方法和结果类型与旧推荐路径并存，独立显示登录／过期／服务失败／真实数量 | 可保留旧兼容和来源事实，需要先确认设计、补契约门并验证真实会话 |

目标界面为发现页“每日推荐”，顶部网易云／QQ／酷狗三平台切换，一次只看一个平台。成功时显示实际曲目数、播放全部、收藏／更多；未登录时显示对应账号入口，登录过期时提供重新连接；服务失败提供重试；结果不足30首按实际数量显示，不用榜单或首页补齐，不修改音源或VIP播放权限。

新增契约为 `MusicPlatform.getPersonalDailyRecommendations({int limit = 30, String? expectedAccountId})`，默认返回明确不支持；原 `getDailyRecommendations()`、`getDailyRecommendation()` 和 `supportsDailyRecommendations` 完整保持。三个适配器按已核实协议覆写新方法，不改变旧回退逻辑。可选 `expectedAccountId` 供新页面校验正在显示的账号，旧调用不传也保留自身凭证绑定检查。

新结果 `PersonalDailyResult` 拟含：真实 `songs`、对应 `platform`、`status`（成功／未登录／身份字段不完整／会话过期／需要平台验证／网络失败／服务不可用／非法响应／空／不支持）、可选 `sourceDate`、获取时间、原始返回数量、有效去重数量、实际展示数量、可选错误码和可重试标志。全部歌曲需先完整解析和身份去重，再按服务端顺序展示最多30首；平台返回32首时明确记录原始32／展示30，不宣称服务端固定30。少于30就展示实际数量，零首显示空态。原始列表非空而全部项身份非法归“非法响应”，不是成功空态；播放全部与展示的有效曲目集合一致。

新provider使用当前账号、会话纪元及请求代次隔离结果；账号变化先清旧个人曲目，迟到响应不能覆盖新账号。请求账号必须与音乐凭证身份一致，ID为0不得当成有效登录。每次异步返回前复核快照；同账号重新登录、换key和A→B→A需要单独纪元／revision保护，不能只比较昵称或用户对象。首版仅内存保存，不新增数据库或依赖；日期来源不明时标“今日获取”，不伪称服务端当天更新。跨自然日的旧响应不得冒称新当天数据，服务端旧日期必须如实显示。未认证或关键身份字段不完整不发个人请求，凭据只由现有客户端在请求内使用，不写入证据、预览、日志或公共文档。

新请求方法用请求级 `Options.validateStatus` 接收需要细分的401／403响应，在共享旧失效广播之前按业务体和响应证据分类。旧共享HTTP层及旧方法不变；新403/WAF不能直接清除账号或假定会话过期；确证过期也只能影响发起请求的同一当前会话纪元。“需要平台验证”显示由用户完成的验证入口，不自动登录或以请求重试绕过平台验证。

实施步骤：完成下面逐平台源码证据与缺口 → 用户讨论确认方案B及新接口接入 → 先写登录／过期／成功30／不足30／超30／空／非JSON／超时／账号切换功能与体验红门 → 新增可选接口与provider → 真实会话验证 → 完整静态和回归 → 新候选构建与成品验收 → 沿既有授权发布。

## 六、逐平台证据与未验证边界

网易：当前产品已有 `/api/v3/discovery/recommend/songs`。公开开源 `NeteaseCloudMusicApiEnhanced/api-enhanced` 固定提交 `23d9e9d7ee5dfeccfc3b15916ccd9da1f76d3ea4` 的 [recommend_songs.js](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/23d9e9d7ee5dfeccfc3b15916ccd9da1f76d3ea4/module/recommend_songs.js#L4) 仍使用这个路径、`afresh` 参数和weapi请求选项，没有30首limit参数。另一个v1模块仅有 `ispush`。现有匿名32首事实保留；不重复探测，不把匿名结果当个人会话证明。

酷狗：公开开源 `MakcRe/KuGouMusicApi` 固定提交 `443d4a416dd344ccf7b022b9fb932e324afc77b4` 的 [recommend_songs.js](https://github.com/MakcRe/KuGouMusicApi/blob/443d4a416dd344ccf7b022b9fb932e324afc77b4/module/recommend_songs.js#L3) 使用 POST `https://gateway.kugou.com/everyday_song_recommend`、路由 `everydayrec.service.kugou.com`、Android签名与用户身份。现有IK已保留token／userid／dfid／mid／uuid等会话字段，但旧推荐方法没有使用该新协议。当前只确认公开源码入口，尚未用用户会话验成功、数量和日期。

酷狗的 [MoeKoe客户端实际消费](https://github.com/MoeKoeMusic/MoeKoeMusic/blob/6dc7067db1f98048e9b6e6c177b967ff39779b28/src/views/Home.vue#L116) 明确读取 `status == 1` 与 `data.song_list`。代理层直接发送业务body，所以原始JSON是 `data.song_list`；没有证据支持在该接口硬套 `list` 或无条件双层 `data.data`。公开客户端使用 `hash / ori_audio_name / author_name / sizable_cover / time_length`，现有旧 `_parseSong` 缺四个新元数据字段，需新增映射保持旧解析器。时长单位还待真实样例核实，不能按字段名猜测。

酷狗 [上游签名](https://github.com/MakcRe/KuGouMusicApi/blob/443d4a416dd344ccf7b022b9fb932e324afc77b4/util/helper.js#L61) 与IK Android方法仅在相同客户端模式、相同参数和相同JSON字符串body时等价；新增方法需明确选择android／lite，并完整处理 [请求头和设备字段](https://github.com/MakcRe/KuGouMusicApi/blob/443d4a416dd344ccf7b022b9fb932e324afc77b4/util/request.js#L92)。旧登录结构能容纳字段，不保证每份会话已具有效DFID／MID；本次设计不包含自动设备注册。上游两日推模块没有limit参数，首页日推展示没有去重／30截断，不能承诺恒定30；其播放全部入队另有hash去重与无hash过滤，不能泛称整个客户端无去重。错误码20028／SSA事件属于安全验证，必须在新状态中增加“需要验证”，不能都写登录过期；尚没有可靠日推专属的业务会话过期码表。

QQ：现有客户端只从musicmac页面抓私享歌单再读详情。核对 [L-1124/QQMusicApi推荐模块](https://github.com/L-1124/QQMusicApi/blob/c046788dd1f11daacc74da487cbbf1bcd8ac6f33/qqmusic_api/modules/recommend.py#L29) 和Rust同类实现，Feed、猜你喜欢、雷达都不是已证明的每日30协议。Python固定提交的modules／models全部38文件已完整读取，没有发现明确daily歌曲模型；这只代表该范围，不能断言官方没有其他接口。另两个开源项目仍采用musicmac私享网页提取，没有确认的新直达日推契约。旧榜单回退与历史失败日志保留，不重复匿名请求，不把通用推荐模块猜成日推。

QQ新增严格日推可先在完整音乐会话下读取明确“今日私享”歌单，再取真实歌曲、去重并展示最多30，读取失败直接显示不可用而不拼榜单。现有 `_personalisedDaily` 会吞错，`getPlaylistDetail` 也会吞错、回退旧公共接口且分页失败仍返回部分结果，新接口不得直接调用这些方法丢失错误或冒称完整成功。

QQ旧 `getDailyPlaylistId` 的正则可以跨越 `</li>`，1600字符邻域又可能取得相邻公共歌单ID。新解析必须绑定同一明确私享卡片与唯一有效歌单ID；仅脚本／注释中的标题、相邻卡片ID、歧义ID均失败，不能根据附近文字推断个人归属。新详情读取须核对顶层／模块业务成功、合法歌曲结构、服务返回的歌单ID（有字段时必须一致）及全部所需分页；分页失败直接明确失败，不退公共榜单或默默返回部分曲目。

QQ两次请求均使用同一内存Cookie快照与音乐身份，结束后重新核对当前账号／会话纪元；快照不输出或持久化。现 `VideoAuthNotifier.sessionEpoch(qq)` 可作为旧请求隔离基础，新增provider另有请求代次；同ID换key需有新可选revision入口，不能仅依赖Cookie getter没有变更通知的状态。musicu旧方法仅原样POST；若以后接新版Android Feed，需 [完整公参](https://github.com/L-1124/QQMusicApi/blob/c046788dd1f11daacc74da487cbbf1bcd8ac6f33/qqmusic_api/core/versioning.py#L89) 及设备会话，不只是换模块名。设备uid／sid与用户音乐凭证分开，QIMEI生命周期不进入此次最小私享方案。当前字段齐全和实际会话有效也需分别验，未读取用户凭据。

新契约的必须接入点为三平台新的API／平台方法、可选个人日推provider、新版发现入口及结果页。现 `RecommendationsNotifier`、`PlaylistRecommendationsNotifier`、`VideoPlaybackPlatform`、歌单详情／导入／平台歌单provider继续用旧方法。实际注册的 `VideoQqPlatform` 可继承新方法；若从 `VideoPlaybackPlatform` 包装器解析，则新增同名转发而不改旧方法。回滚只关闭新版个人入口／新provider，原推荐、私享与公共回退路径及会话存储完整保持。

个人日推门必须覆盖：未登录／缺字段／音乐ID0不发请求；私享相邻卡片／注释／歧义ID；0／1／29／30／31／32首及重复／全非法项；完整分页与第二页失败；返回ID不符；同用户换key／A→B→A／跨日迟到；非JSON/WAF／20028-SSA／未知业务码／超时；旧403行为保持、新WAF不清账号、旧请求迟到401不退出新账号。全部状态的界面提示、按钮启用／禁用和原动作对应先写红门，再实现。

三平台源码研究均没有取得真实用户个人成功响应；这些是可执行实现方向，不是已安装功能或真实账号验收。拟新状态还须覆盖“身份字段不完整／需要平台验证”；错误码仅按确证分类，未知码显示真实服务失败，不虚构过期原因。
