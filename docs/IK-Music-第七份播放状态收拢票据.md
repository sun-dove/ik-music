# IK Music 第七份播放状态收拢票据

日期：2026-11-26。用户新截图指出常驻播放提示占据底栏整行，且收藏与其他按钮的对齐不合理；随后明确继续。此次仅修正快速预览的呈现，不修改播放候选、时间预算或自动切源规则。

## 一、真实场景

第六份显示“已尝试5个候选，剩余53个；可继续尝试”的整窗横幅。它表示本轮取流时间预算用完、仍有未试的音源与音质组合，不表示所有音源失败，也不是歌曲数量。现有状态有精确 `canContinue`，应由此驱动按钮，不能通过中文关键词推测错误类型。

体验目标为歌曲旁的简短状态和恢复入口；详细次数、每个候选失败原因只在用户点“详情”时查看。主页面与独立播放详情底栏使用相同呈现。成功或恢复中不残留失败提示。

## 二、方案与最小改动

方案 A 将大横幅压成全窗一行，仍与整条播放栏争抢高度，不采用。

方案 B 新增局部 `IkPlaybackNotice`，放在左侧歌曲组旁，空间不足时在左组内分行。失败时替代辅助歌词，保留歌曲和收藏；详情底栏虽无辅助歌词，也使用相同局部状态。采用 B。

“详情”使用项目既有 `MenuAnchor` 锚定面板样式，限制宽高、内容可滚动，支持外部点击、Esc和关闭按钮；不使用底部弹窗，不缓存跨歌错误。只含标题、原始错误、候选记录及可用恢复动作。没有失败时该组件不挂载，不占空行。

本项是既有错误呈现的小修。新组件独立；`IkPlaybackBar` 仅已启用 `balancedLayout && contextualErrors` 的Windows快速分支使用它，旧 `_errorNotice` 和缺省分支保持。没有新依赖、存储、外部接入或接口签名变更。

## 三、状态和调用方

- 静态失败：`player.error` 非空、`!player.isPlaying`、`!player.isTransitioning`、`!source.busy`。
- 重置失败：精确等于 `IkContextualErrorStrings.playerResetReason`，提示“播放恢复未完成”，提供原重新播放动作。
- 预算可继续：非重置且 `source.canContinue`，提示“暂未播放成功”，提供 `MultiSourceVideoPlayerNotifier.continueSources()`。
- 其他失败：提示“暂时无法播放”，有当前曲目时提供原 `playSong` 重试；不通过字符串判断网络故障。
- 详情展示 `player.error` 和 `source.details` 的原文；相同整段只出现一次。成功后即使历史 `source.details` 仍有失败记录，也不显示失败状态。
- 恢复中由原播放按钮加载状态表达，隐藏旧失败；现有开始播放／继续尝试路径负责清除错误。

装配点为 `ik_playback_bar.dart` 新布局左组。原 `SourcePlaybackView`、播放器、session、源更新、账号和歌曲数据保持。

## 四、待验门与回滚

| 场景 | 体验门 | 功能门 |
| --- | --- | --- |
| 时间预算耗尽且仍有候选 | 左组简短状态，可继续，不占整窗横幅 | 仅真实canContinue显示继续按钮，调用原continueSources |
| 候选耗尽或其他失败 | 可查看原始原因，有曲目时可重试 | 不把未尝试候选写成全部失败，不猜测网络错误 |
| 播放器重置 | “播放恢复未完成”与重新播放 | reset判断优先，不沿用旧canContinue |
| 恢复中／播放成功／切歌 | 不残留旧失败条与面板 | busy、transition、playing优先；不缓存跨歌错误 |
| 窄窗与较大字体 | 状态和操作在左组可换行，面板受屏幕宽高约束 | 无固定整窗横幅，不影响中央seek和右工具 |
| 原入口 | 既有提示保持 | balancedLayout false不挂新组件 |

用户持续要求快速编译且暂停tests/analyze/format/GUI；以上是待验规格，未运行，不以源码阅读冒充体验门绿。回滚仅撤新分支装配和新增组件／文案，恢复第六份横幅；无数据迁移。

Jev布局参考已实际调用jev-latest，返回模型jev-1.14.0：收藏在歌曲组0.42、中央控制组0.57、歌词组0.01，confidence0.35，结论不确定，未作为唯一设计依据。最终按已向用户说明且用户继续授权的方案，收藏固定在歌曲信息旁，左右整组与中央两行垂直居中。对应布局见《IK-Music-第七份底栏整体对齐票据》。
