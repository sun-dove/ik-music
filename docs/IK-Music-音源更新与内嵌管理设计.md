# IK Music 音源更新与内嵌管理设计

## 背景与授权

2026-11-26 用户明确要求音源管理嵌入设置、左侧分类固定、保存及更新操作移到顶部，补齐单项／批量／自动更新，缩短失败切源等待，并保证改音源不打断正在播放的歌曲。本轮继续用户已经授权的 Windows 快速预览，只编译，不运行新增测试、静态分析、格式检查或 GUI 验收；以下场景门目前均为待验规格。

原有“自动准备”只下载随包固定目录；`prepareCatalogUpdate` 不查远端新版。管理页的“批量检测”只初始化脚本，单项更新按 origin 导入又可能改变受管条目的身份，不能改标签充当真正更新。

## 方案对比与选择

- 方案 A：让原管理页直接更新 origin，并把自动准备改名为自动更新。改动少，但固定提交永远拿不到新版，受管 ID 可能重复，编辑草稿和后台发布会互相覆盖，不采用。
- 方案 B：保留固定目录准备和旧入口，Windows 新入口增加更新协调器。检查只下载比较内容；单项和批量更新先用现有隔离运行时初始化，再返回草稿，顶部保存提交。自动更新独立开关，缺省关闭，每天在没有编辑／切歌任务时检查并保存。采用此方案。

页面采用固定左分类、右侧固定操作栏及独立滚动正文。更新检查不离开页面，结果显示在操作栏附近；内置目录的版本和许可资料默认收起。普通错误显示在本页，不新增底部弹层。

## 接口与数据

新增 `IkSourceUpdater`，通过可空 Provider 仅在 IK Windows 装配。提供 `checkUpdates(CancelToken)`、`updateEntry(SourceEntry, CancelToken)`、`updateAll(SourceCollection, CancelToken)`、`saveDraft(SourceCollection)`、自动更新偏好及状态。管理页新参数缺省关闭；批量返回同一顺序和 ID 的新草稿，保留启用状态、下载权限、首选和排序。

新增获取器只读取 pdone 仓库已知目录：先解析主分支提交，再使用该提交的树与固定文件 URL，核对 Git blob 哈希和字节数后才允许初始化。最新文件是符号链接时只解析同一树内安全目标。自定义源继续其原导入 URL，绝不擅自换服务器。单文件最多 1 MiB，获取有总时限，复用原 HTTPS 和公开地址限制。检查不会执行脚本。

受管记录增加可选 `followsUpstream=false`。成功更新保留旧版本供回退，并标记跟随上游，避免下次启动的固定目录准备把新版覆盖回旧版；未升级记录与旧入口缺省行为不变。自动更新偏好与最后检查时间使用独立键，不写入账号凭据。失败保留旧配置，取消不发布半成品。

播放修复另见播放恢复票据。当前媒体与切源候选的生命周期分开；保存后已加载媒体继续，后续取流读取新策略。Windows 快入口使用较短尝试预算，旧入口仍原计时。

## 调用方与回滚

受影响调用方：`main_video.dart` 的 IK Windows 装配，`video_app.dart` 的设置／音源入口，`IkSettingsWorkspace`、`SourceManagerPage`、`IkSourceCatalogPanel`，受管设置新增提交方法及固定目录准备对新增可选标记的判断。其余入口不启用新参数。

回滚时关闭 Windows 新装配参数，移除更新 Provider 的装配即可恢复旧界面与旧计时；保留既有音源和新增可选元数据，不能删除用户音源。旧代码忽略新增 JSON 字段。

## 实施顺序与待验场景

1. 写入本设计和页面／播放票据；新增获取器与更新协调器。
2. 接入有界内嵌管理、固定操作栏及草稿保护，再接 Windows 入口。
3. 只做独立预览编译，交给用户实际查看。

待验功能门：无更新／有更新／网络失败／限流／哈希失败／初始化失败／取消均有明确状态；全部更新不重复 ID，不丢排序和开关；失败项旧配置仍在；自动更新关闭时无周期请求，开启后按日检查，编辑时暂缓，退出时取消；固定目录不降级已跟随上游的条目；回退后自动更新不立即覆盖。

待验体验门：滚动源列表左栏和保存按钮不移动；检查、单项和全部更新有进度和逐项结果；有草稿时切分类／主导航／HTTP配置都能保存、放弃或继续；正在播放时保存音源不断歌；失败切源不叠加原长等待。用户暂停验证期间不得把上述规格记作通过。
