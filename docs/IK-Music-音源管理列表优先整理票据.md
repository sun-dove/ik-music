# IK Music 音源管理：列表优先整理

2026-11-26。用户确认「那你看着改一改，要加的加。然后把音源管理里面整理一下，有点乱」，并授权接续此前讨论的智能均衡。此票据只处理 Windows 设置里内嵌音源管理的展示；智能均衡候选与偏好沿用单独的设计。

## 目标与方案

真实场景：已有 20 个音源、19 个启用，希望看见首选、查找某个源或调整顺序。旧页面把链接输入、更新按钮、自动更新与目录放在列表前，固定工具区最多占可用高度的 48%；未修改也能点保存。方案一把这些工具折叠在列表前：距离短，但展开后再次挡住列表。方案二是保留一个顶部标题、计数与保存入口，下面在「已添加音源」「更新维护」「添加音源」三种就地视图间切换。采用方案二：日常列表是首页；检查／批量／自动更新同处；输入链接、本机导入、HTTP 和内置目录集中到添加页，可在任何视图切回。不增加独立路由，也不截断全部 20 项。

列表显示当前质量、自动切源和播放顺序摘要，可按需调节。选音质走应用统一入口即时生效，不再叠加一个独立的最高档开关。首选、排序、启用与自动切源仍是同一份待保存草稿。后台运行或有可处理的维护失败时，列表显示短提示，允许查看涉及的更新或导入视图；运行中不能重复提交更新或导入，仍可浏览筛选和编辑草稿。

## 接口、调用方和回滚

`SourceManagerPage` 新增缺省关闭的 `organizedLayout`。可选的 `playbackQualityControl` 直接接收播放设置使用的选择器，当前值、可选档位和写盘处理都由同一控件提供；`updatePanel`、`localImportPanel`、已有 `catalogPanel` 各放一次；`maintenanceNotice` 与缺省为假的 `maintenanceNoticeIsImport` 用于需要操作的摘要和跳转位置。更新成功的回执留在维护分区，进行中的工作或需要处理的失败才在列表提示。分区本身没有新增持久化字段。只有 `VideoMusicApp` 的 Windows 快版 `_embeddedSourceManager` 主动接入；独立源管理、旧内嵌构造、Android、播放器与下载接口默认不变。去掉该注入并把三项面板按旧方法传入即可回滚，无需迁移设置。

## 实施步骤与验收门

先在原版复现首屏找不到源、没有分区、无更改可保存，再加局部布局与可选注入，用实际组件完成以下正式长期回归门，同时复跑旧菜单、导航和管理门：

| 使用场景 | 界面与数据验收 |
| --- | --- |
| 20 个源、19 个启用 | 常见 Windows 正文尺寸首屏可点首源；能查看首选，首屏无链接、批量更新和目录长表；可滚动到第 20 项再回到顶部。 |
| 筛选与草稿 | 平台、名称与启用条件筛选实际结果；无更改不能保存，修改后可保存一次；切视图／更改音质后保留筛选、未提交来源和当前顺序。 |
| 更新与添加 | 进入对应视图可检查、批量更新、导入、查看本机与目录；在后台忙时可回列表、筛选、继续改草稿；防重复操作，可看失败详情或取消。 |
| 边界 | 空集合指向实际添加页，筛选为空可恢复；窄窗与放大字号可访问各控件，旧页面不受影响。 |

正式 `VideoMusicApp` 在添加分区挂载内置目录时，Flutter 报告 `ListTile` 的点击反馈被同色装饰背景挡住。受影响的是 `IkSourceCatalogPanel` 的 `refinedLayout` 分支：Windows 音源管理的精简目录面板；默认目录不使用这一分支。将原装饰背景交给同形状的 `Material` 绘制，保持尺寸、交互、数据与回调；回滚只需还原该分支的装饰容器。正式入口门应能从列表进添加分区，再回播放设置，三个位置均无绘制异常。
