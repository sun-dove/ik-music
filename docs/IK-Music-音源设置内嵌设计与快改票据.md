# IK Music 音源设置内嵌设计与快改票据

日期：2026-11-26。状态：设计已由主任务确认，按用户继续改版的授权制作快速候选；本轮暂停测试、静态分析、格式检查、GUI 与构建验证。本票据所列新门全部待执行，不把源码落盘记为验收通过。

## 一、问题与目标

当前设置的音源分类展示内置目录，管理入口在二十项资料之后；点击后又打开带独立标题栏的管理页面。设置分类与右侧正文共用外层滚动，长列表会将左侧分类和常用操作一起卷走。用户要求在同一设置正文完成音源管理，保存、手动导入、检查更新、全部更新靠近顶部，左侧分类固定。

本次只扩展 IK 快速改版入口。原页面构造、默认布局、手动导入公开契约与存储结构保留。实际更新服务与播放器行为由主任务负责；本票据的界面实现只消费明确回调，不把固定目录准备或批量检测改名成更新。

## 二、已核对的现有能力

| 能力 | 现有实现与边界 | 本次使用方式 |
| --- | --- | --- |
| 自动准备 | `main_video.dart` 首帧后调用 `prepareOnce`；开启 `autoPrepare` 时也调用。只读取随包固定目录，不周期请求远端最新版。 | 保留原名称、开关和行为；与新增真正自动更新分开。 |
| 检查当前目录 | `prepareCatalogUpdate` 获取或校验当前随包版本，跳过已匹配、停用、移除和回滚锁定项目。 | 保留在内置目录资料中，可隐藏重复的顶部按钮。 |
| 手动导入 | 管理页调用 `onImport(link, token)`，通过后写入本页草稿，保存后生效。 | 新版顶部内联链接输入，仍走原导入回调。 |
| 单项更新 | 原管理页更新操作等于重新导入 `entry.config.origin`。 | 旧默认保留；新回调返回新配置后按原 `entry.id` 替换，保留启用和下载选择。 |
| 检测当前列表 | `_inspect(entries)` 顺序初始化筛选结果，逐项记录成功、失败、取消。 | 继续称“检测列表”；不伪装成批量更新。 |
| 全部更新 | 原管理页没有该能力。 | 主任务新增更新服务；界面提供有取消令牌且返回新草稿的回调。 |
| 草稿离开保护 | 管理页保存、放弃、继续编辑三选；保存失败留在原页；`IkWorkspaceNavigation` 覆盖工作区主导航。 | 同一检查还需覆盖设置内部分类和外部 `sectionRequest`。 |
| 自动发布暂停 | `IkSourceEditingScope` 挂载时暂停发布、卸载时恢复；受管设置按编辑基线合并。 | 只在音源编辑正文实际显示时挂载，隐藏的 `IndexedStack` 设置页不持有租约。 |

受管目录条目的稳定 ID 使用 `sha256('ik:sourceKey')`，原 `SourceCollection.upsert` 则按 origin URL 计算 ID。新的受管更新不能直接沿用 `_import(origin)`，否则可能新增重复条目。新回调必须返回配置，界面使用既有 `replace(entry.id, config)`；批量返回保持身份与排序的新集合。

## 三、方案比较

| 方案 | 实现 | 优点 | 代价 |
| --- | --- | --- | --- |
| A：只把管理按钮移到目录顶部 | 保留独立管理路由，其余只做样式调整。 | 改动少，现有路由保护无需扩展。 | 仍然跳转第二套页面；左栏滚动、长目录和保存位置问题未完整解决。 |
| B：设置有界正文内嵌原管理状态 | 设置新增固定布局和可选 builder；管理页新增内嵌布局，复用原草稿、导入、检查与保存。 | 同一设置页面完成操作；主要行为复用；旧入口可继续工作。 | 要补设置内部切换保护，并按可见性管理发布暂停。 |
| C：重写音源管理状态和存储 | 新模块同时管理目录、远端更新、草稿、持久化与播放器通知。 | 可统一全部状态。 | 改动面大，重复既有保存和保护逻辑，增加兼容风险。 |

采用 B。真实更新单独由主任务实现，现有页面只增加可选回调与新布局分支。默认参数保持旧行为，回滚可只关闭新入口参数。

## 四、可选接口与数据边界

### 设置工作区

`IkSettingsWorkspace` 新增：

```dart
bool fixedNavigation = false;
bool active = true;
WidgetBuilder? sourceBuilder;
```

`fixedNavigation` 启用有界布局：标题在顶部，宽屏左分类固定、右正文独立滚动；窄屏分类在顶部横向滚动，正文独立滚动。其他分类仍使用现有内容。源管理 builder 自带有界滚动，不再套入 `SingleChildScrollView`。根入口必须准确传入 `active`：设置未选中、独立详情路由遮挡或命令式正文覆盖时为 false。只有 `active && 当前分类为 sources` 时挂载 builder。

### 管理页面

`SourceManagerPage` 新增：

```dart
bool embedded = false;
bool refinedLayout = false;
Widget? catalogPanel;
Future<void> Function(CancelToken)? onCheckUpdates;
Future<SourceCollection> Function(SourceCollection, CancelToken)? onUpdateAll;
Future<LxSourceConfig> Function(SourceEntry, CancelToken)? onUpdateEntry;
String? Function(SourceEntry)? updateStatus;
```

原必需参数与默认值不变。`embedded` 去掉第二套 `Scaffold/AppBar`，不在嵌入返回动作里弹出父路由。`refinedLayout` 提供顶部固定操作与正文；异步操作继续共用 `_run` 的忙碌和取消状态。

检查更新不修改草稿。全部更新返回新草稿，仍需保存；失败由回调抛出既有异常语义并显示原错误，不能清空既有集合。取消批量更新后仍接收回调返回的已完成结果，不丢掉前面已准备的草稿；摘要由更新服务和逐项状态提供，界面不把一次回调返回等同于全成功。单项更新保留原 ID，并直接采用更新器返回的配置，由更新器保留用户选择和强制下载限制，界面不能再次把受限下载开关开启。没有真实回调时，不渲染该更新按钮。主任务提供 `IkSourceUpdater` 与 `IkSourceUpdatePanel`；自动更新状态、最后检查时间和逐项结果由该组件及 `updateStatus` 展示，界面层不自己创建轮询器。

`IkSourceCatalogPanel` 新增 `refinedLayout = false`、`showCheckAction = true`。新版把完整内置目录资料默认折叠，保留全部条目与真实状态、许可、固定版本和失败重试；开关继续叫“自动准备内置音源”。它可与主任务的更新状态组件共同传入 `catalogPanel`，不会重复铺出第二套二十项主列表。旧恢复、回滚和策略直写入口只留在原默认页：它们会直接改已保存配置，不能在内嵌编辑过程中绕过草稿；新版恢复或回滚需更新服务先返回草稿后保存，本次界面不虚构该能力。

## 五、草稿与生命周期

1. 设置的 builder 下新增局部 `IkWorkspaceNavigation` 代理。子页注册时，同一检查同时记入当前分类表并向外层登记；注销时两处同时注销。外层主导航与页内分类因此复用管理页的 `_pendingLeave`，不重复弹三选。
2. 内部点击分类、外部 `initialSection/sectionRequest` 请求先等待检查，成功后才切换。外部请求在本帧构建完成后执行，避免在构建过程中弹框。连续请求共享当前检查，最终采用最后一次有效目标；拒绝或保存失败则留在音源分类。
3. 管理页忙碌时拦截离开，显示取消入口。取消只结束当前操作，等待收口后再离开，不在中途丢弃状态。
4. 保存成功更新基线；保存失败保持 dirty 和编辑正文。新嵌入页选择放弃后还原已保存基线并清 dirty，再由实际分类或根导航卸载，避免外部先查一次、内部处理分类请求时重复询问。下次进入重新读取已保存集合。
5. `IkSourceEditingScope` 仅包住实际挂载的管理编辑器。保存后仍在编辑页面时继续暂停自动发布；切分类、离开设置或路由遮挡后释放。根入口不可在永久保留的整个设置树外套该 scope。
6. 嵌入分支没有“返回上一独立管理路由”的按钮。系统返回仍受 `PopScope` 与已注册离开检查约束，不能无条件 `Navigator.pop` 父工作区。
7. 分类正文使用按分类和可见性重建的局部 Overlay，切分类或隐藏设置时，所属菜单与 Tooltip 同步退场。顶部管理操作最大占可用高度的 48%，异常提示最大占 18%，不足时独立滚动；左侧分类在自己的 Expanded 内滚动，不跟右侧正文联动。

2. 扩展 `source_manager_page.dart` 新布局、更新回调、现代操作菜单与嵌入返回分支；旧默认路径保留。

回滚：根入口撤掉新布局、builder 与更新回调参数，即回到现有目录页和独立管理路由；不删除音源集合、墓碑、用户策略、检查记录或备份。不通过改旧存储键完成回滚。
