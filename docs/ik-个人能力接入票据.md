# ik 个人能力接入票据

日期：2026-11-20。实施依据为用户本轮“在这一版都做完”和《ik-完整改版实施与验收》，属于已确认 K04/K06 场景的兼容接入。

## 问题与方案

现有音效应用会吞掉后端错误，Android 参数准备还可能异步失败；如果独立页仅绑定保存设置，就会显示已开启而没有实际效果。睡眠定时每十秒保存剩余时间，原独立运行时监听整份设置，会不必要地重复应用 EQ 和恢复音量。备份文件选择器返回 UTF-8 字节，按 `String.fromCharCodes` 解码会破坏中文。收藏/历史默认分别只读取 500/200 条；独立聚合页不能把它们表示成全量。现有跨 SQLite、JSON、Hive 的备份合并也不能宣称天然具备整体事务。

方案 A：新建独立音效状态适配，新增可验证的可选后端能力；保留旧音效 API。收藏/历史新增明确的全量方法；备份增加独立安全恢复路径与 UTF-8 解码，旧接口保持。方案 B：统一重写所有播放器、库、备份公共方法。采用 A，减小生产改动并保持 Mconnect 默认。

## 接口、调用方和回滚

| 接入 | 受影响调用方 | 兼容与回滚 |
| --- | --- | --- |
| 新 `VerifiedEqualizerCapable`、`applyEqualizerSettingsVerified` | 仅 ik 音效运行时；Android 通知托管控制器转发该可选能力 | 原 `applyEqualizer`、`applyEqualizerSettings` 行为保持；移除 ik 适配即可回滚 |
| 独立音效状态与桌面状态 | IkRuntime、IkAudioPage | 只在独立改版树中建立，不新增第二播放器 |
| 新收藏/历史全量加载方法 | ik 曲库、备份导入后刷新 | 原 `loadLikes`/`loadHistory` 数量和签名保持 |
| 备份 UTF-8 文件解码 | BackupPage 文件选择器路径 | 仅修复文件编码；合法 ASCII 文件保持相同行为 |
| 独立安全备份存储 | ik 对 BackupService provider 的 override | 导入前完成解析与持久恢复点；失败显式报告恢复结果，不能把部分写入称为成功 |
| 小组件绑定释放 | IkRuntime | 保留原 attach 默认，只增加按同容器解绑方法 |
| 严格桌面歌词结果与设置回调 | ik 浮歌词运行时、独立设置包装；共享设置页新增可选回调和状态区 | `strictDelivery=false`，旧设置页缺省行为保持；ik 失败显示提示且可重试 |
| 智能歌单安全删除 | ik 智能歌单页 `safeDelete=true` | 新增 `deleteRuleSafely`，规则保存失败不继续删快照；旧删除方法保留 |
| 链接生命周期 | IkLinkRuntime，当前 Player、独立 Router、待导入文本 provider | 保留旧 mconnect 链接协议；不导入原全局 Router，插件失败不影响启动，销毁后迟到初始链接不执行 |
| 多源控制器音效转发 | `_SourceAudio` 的可选 `VerifiedEqualizerCapable` | 不改旧播放/解析流程，只透传底层支持及真实错误 |
| 平台歌单账号切换 | 独立账号运行时 | 账号 id 变化后清旧 provider 并加载新账号；旧 provider 默认不增加认证依赖 |

## 可执行门

1. 音效后端真实拒绝、抛错、成功分别产生不可用、失败、成功状态；睡眠剩余时间变化不触发 EQ/音量写入；重试能恢复。
2. 文件字节包含中文歌曲/歌单/字体时导入导出不变；无效 UTF-8 在写入前拒绝；中途设置写入失败能恢复原歌曲/收藏/歌单/规则/设置，恢复失败保留恢复文件并明确路径。
3. 501 收藏和 201 历史能通过新增方法完整读取，旧加载门继续保持 500/200；平台加 ID 作为实体标识。
4. 音效页可见应用状态、重试或禁用状态；倒计时与取消动作正确。Windows 通道连接失败与消息失效可观察；消息仅调用当前 Player。
5. 桌面歌词权限拒绝时保持关闭，重试确认原生窗口创建成功后开启；无歌词切歌刷新占位而不残留上一首。智能歌单规则写失败时规则及快照均保留。

正式验收门作为交付保留，临时样例由测试自身在完成后精确删除。实际结果追加在本文件末尾。

## 追加：导入期间睡眠计时写入屏障

最终兼容审查发现：睡眠计时每十秒会通过当前 `AudioEffectsSettingsNotifier` 写入整份音效设置。如果导入后只提示重启，旧内存的 EQ/淡入设置可能在下次计时保存时覆盖已导入值。这属于 K06 备份场景的数据正确性缺口，用户已授权在本版修复。

选择专用导入服务包装，保持默认 BackupService 和 SleepTimerNotifier 的原入口行为。用户确认导入后，同步停掉当前计时 tick，等待已经发出的计时持久化完成，之后才创建恢复点并开始导入；成功时依次销毁旧计时 provider、旧音效适配、旧音效设置 provider，再从已导入设置重新建立它们。失败时恢复原计时，不写入额外旧设置；解析失败也经过 finally 恢复。导入中的 UI 操作不能令旧计时再次写盘。窗口仍可播放音乐，统计使用原数据库事务顺序。

受影响调用方只有 ikBackupServiceProvider 及新增 `IkBackupService`；SleepTimerNotifier 增加可选显式暂停/恢复方法与待写跟踪，不改变 `setEnabled`/构造/缺省行为。回滚可移除 ik 服务包装，不改磁盘格式。新增正式门先验证缺失导入屏障为红，再验证：已有保存阻塞时导入不能先写、导入等待超过十秒仍不写旧音效、成功后 EQ/淡入/计时与备份一致，失败后原计时继续。

实际结果：`ik_backup_timer_barrier_test` 缺少专用服务时真实红（编译缺模块，8 秒）。实现后 3 门通过，覆盖已发出计时写入的等待、导入期间跨 30 秒且用户重新开启仍不写旧值、导入成功 30 秒后新 EQ/淡入/睡眠值保留、解析失败与存储失败后旧倒计时继续。与原 `sleep_timer_provider_test`、`ik_backup_recovery_test`、`database_backup_test`、`audio_enhancement_settings_test` 合计 25 门全部通过、0 跳过，测试报告耗时 7 秒。计时推进使用 Flutter 已有测试框架，不增加生产依赖。
