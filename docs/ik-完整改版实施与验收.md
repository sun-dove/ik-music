# ik 完整改版实施与验收

日期：2026-11-20。基线 `bf6d73f`（0.5.1 候选）。用户本轮明确要求：“继续。在这一版都做完，并且把名字换成ik。然后把桌面图标要换了，然后我的下面要这个做什么”。本要求确认已有改版设计的完整实施范围，取消原先按 0.6/0.7/0.8 分别交付的安排，合并为一个 0.6.0/build 10 完整改版候选。开发在 `feature/ik-complete` 进行。

## 目标与方案

目标是让当前独立产品实际可访问内容发现、跨来源搜索和曲库、详情与个人能力，同时补齐 Windows 操作。名称统一小写 `ik`；“我的”页标题下重复品牌副标题移除，版本保留页尾。桌面快捷方式显式绑定新版 ICO，覆盖安装时按目标核对迁移旧品牌快捷方式。

方案 A：新增独立路由、现代导航壳、聚合控制器与运行时装配，通过可选参数接入旧 `VideoMusicApp`，复用现有内容页与 provider；Windows 新能力使用独立原生通道。方案 B：直接修改 Mconnect 路由、所有旧页面与播放后端，统一两个产品。采用 A：符合用户向后兼容要求，既有构造默认、Mconnect 路由、包名、证书与数据目录不变；避免为了导航改变生产播放算法。两方案的详细比较、数据模型和错误状态沿用《DJ-Music-改版设计与验收计划》。

## 接入点、调用方与回滚

| 接入点 | 调用方与变化 | 回滚 |
| --- | --- | --- |
| VideoMusicApp、VideoHome、main_video | 新增缺省关闭的 redesign 选项，独立 main_video 显式启用路由和四导航 | 停用选项回到旧五页，不迁移数据 |
| 搜索控制器/曲库页面 | 新增四来源独立状态、分页/重试/代次与来源筛选，旧 VideoCatalog 接口和旧页面保留 | 旧页面继续可用 |
| 独立运行时 | 绑定同一容器的统计、历史、音效、睡眠、悬浮歌词与小组件；复用已有 provider | 移除独立装配，不删除设置 |
| Windows runner | 新增托盘/窗口记忆/单实例/SMTC和最小尺寸，只在 YUEYIN_BUILD 启用 | 取消新通道和窗口适配，旧关闭策略保留 |
| 品牌与构建 | 独立版本清单、显示名、图标和安装器迁移；不改公开包名/签名/CompanyName/ProductName | 更高版本恢复显示资源，数据不动 |
| 主题和设置 | 新主题扩展只在 redesign 使用，旧配色默认值不变；删除重复副标题 | 停用新主题与页面装配 |

## 场景、接口与验收门

| 场景 | 功能门 | 体验门 |
| --- | --- | --- |
| K01 辨认应用 | 名称/独立版本/原身份一致，ICO绑定正确 | 桌面 ik；“我的”没有重复品牌副标题；页尾版本正确 |
| K02 四主区与详情 | 独立 Router 全部路径可解析，非法平台/缺参数显示错误页 | 四导航、返回与迷你播放器保持；榜单/专辑/歌手/歌单可达 |
| K03 聚合搜索 | 每来源独立请求/分页/重试；迟到旧词结果丢弃；部分失败保留成功 | 来源标识、筛选、加载/空/失败/重试各自可读可点 |
| K04 我的音乐 | 平台收藏与本地收藏写操作隔离，来源+ID唯一；账号失效清对应列表 | 筛选/登录/同步进度；歌单/下载/本地/历史可达 |
| K05 首页与发现 | 已注册平台按能力和真实账号调用，失败不虚构内容 | 继续播放、推荐、新歌、榜单及错误/重试入口 |
| K06 播放与工具 | 全部复用同一 player；音效监听实际应用；统计/睡眠/悬浮生命周期 | 右侧队列、音源卡片、均衡器、定时、悬浮歌词、统计、智能歌单、备份入口和反馈 |
| K07 Windows | 单实例、窗口边界/记忆、托盘控制、媒体命令与资源释放 | 第二次启动唤醒；托盘找回/退出；系统媒体信息与可操作状态 |
| K08 视觉 | 新主题字号/语义颜色令牌及旧默认不变量 | 深浅、320/720/900/1200宽度、100/125/150%字号无溢出 |
| K09 构建升级 | 单一独立版本清单、静态分析、完整回归、原生门、签名/身份 | 新包覆盖安装、图标、旧数据和实际导航验证 |

新增控制器使用 `Map<PlatformType, IkSearchGroup>`，状态含 query、generation、songs、page、total、hasMore、loading、error。来源实体使用平台+ID；不同来源同名歌曲保持来源，不静默删掉可能可播放的版本。既有内容页继续在原 provider 契约下运行。
