# IK Music 0.6.2 使用与构建

**版本：IK Music 0.6.2 / build 13。** 本文介绍应用的使用方式、平台能力边界，以及源码构建与发行核验要求。各次构建、测试和安装的实际结果由对应验收记录与文件清单说明。

项目仓库为 [sun-dove/ik-music](https://github.com/sun-dove/ik-music)。桌面、Android 和应用内显示 **IK Music**，继续使用用户提供的渐变音符图标。Android 包名与稳定签名、Windows 安装身份、内部程序名和用户数据目录保持兼容。Windows 新装默认目录是 `%LOCALAPPDATA%\Programs\ik-music`，更新沿用已有登记目录。

## 这一版调整了什么

这一版统一普通详情页的导航，收拢重复推荐入口，调整独立播放详情的排版，并修复标签切换、音源下拉和歌词手动浏览后的跟随。音乐库、搜索、下载、账号、备份、音源和音频处理继续使用既有数据与业务接口。

| 场景 | 0.6.2 的操作方式 |
| --- | --- |
| 打开歌单、专辑、歌手、榜单、下载、统计或编辑页面 | 正文在主界面内打开，保留主导航、共用搜索与底部播放栏；返回恢复原主区状态 |
| 打开播放详情 | 使用独立页面，隐藏主导航和共用搜索，仅保留一份播放控制；返回原页面 |
| 找个人每日推荐 | 从发现页的“每日推荐”进入；搜索空白页保留热搜与手动搜索入口 |
| 切换音乐库五分类 | 标签占位一致，选中不会下沉或推动相邻标签 |
| 改音源播放策略 | 在原位置展开自定义菜单，选项有说明和选中标记，列表不被推移 |
| 手动浏览歌词 | 滚动或拖动结束后无操作三秒，平滑回到当时正在播放的歌词；不改变播放进度 |
| 切换页面时还有编辑内容 | 按页面提示继续编辑、放弃或使用既有保存操作；正在保存或解析时先等待完成 |

系统文件选择器、确认窗口、系统登录授权与桌面歌词浮窗继续使用各自的独立窗口。它们不属于普通二级内容页。

## 主界面、导航与搜索

主界面有 **发现、搜索、音乐库、最近播放、设置** 五个主区。顶部显示当前主区，共用搜索框输入歌曲、歌手或专辑后按 Enter 执行查询。切换主区保留已访问页面的输入、筛选、分类和滚动状态；从详情返回时仍处于进入前的页面。设置分区和音源管理通过正文标题标明具体页面。

普通详情使用同一正文导航，包含歌单、专辑、歌手、榜单、新歌、推荐、登录、下载、缓存、统计、智能歌单、导入和备份入口。无效路径或参数在主界面内显示错误并提供返回操作。队列和专辑等页面可以从播放详情进入，再逐层返回；独立播放器与普通正文各只显示自己需要的一份播放栏。

搜索空白页只展示现有接口返回的热搜词；点击热词进入原搜索，可展开更多或收起。查询本地、网易云、QQ 音乐和酷狗的结果，保留来源筛选、各来源独立加载、翻页及重试。热词失败会显示实际原因，仍可手动输入。清空查询回到热搜，个人每日推荐不会重复铺在搜索页面。

音乐库中的“喜欢的音乐、我的歌单、本地音乐、下载、智能歌单”在原位置切换。窄屏可以横向滚动分类。收藏、本地分组、多选添加歌单、导入导出、下载、离线缓存和智能规则继续可用。最近播放记录已经听过的曲目；播放队列表示接下来要播放的曲目，由底栏按钮按需打开。

## 发现与每日推荐

个人每日推荐集中在 **发现 → 每日推荐**。选择网易云、QQ 音乐或酷狗后只显示当前平台结果。发现页的额外推荐卡片只展示已明确标注的榜单推荐或首页推荐，保留真实出处，不重复展示个人日推。兼容的旧推荐路径仍可打开，但不会在搜索空白页再放一个相同推荐入口。

个人日推需要对应平台的有效音乐会话。网易云、酷狗读取各自个人推荐；QQ 只读取明确的“今日私享”卡片及完整歌单分页。完整解析并去重后最多显示30首，不足30首显示实际数量，不用公开榜单补齐。播放全部只使用当前页面展示的曲目。账号或凭据改变、退出登录以及跨日后清除旧个人结果；日期未获平台确证时只标获取日期。

未登录、登录信息不足、会话过期、需要平台验证、网络失败、服务错误和空结果分别显示。用户自行完成平台登录或验证，重试只作用当前平台。新歌和榜单保留顶部平台选择，新歌地区筛选及平台不支持说明不变。

个人推荐的可用性取决于平台服务与账号会话。平台返回服务失败或登录信息不足时，页面保留对应原因与重试／连接入口；已有公共推荐不能替代个人推荐结果。不同平台、不同会话和日期的结果应按当时响应分别确认，不能因另一个推荐入口有歌曲就认定个人推荐已成功。

## 独立播放详情与歌词

点击底栏当前歌曲打开独立播放详情。宽屏采用左侧封面与信息、右侧歌词的紧凑布局，内容宽度有限制，减少封面、来源与工具之间的无效留白。窄屏在顶部并排显示小封面与歌曲信息，下方保留歌词及播放控制；信息较长时可以独立滚动。

歌曲名称、歌手和专辑靠近封面。只有真实歌手或专辑标识可用时才提供跳转，不根据同名猜测。来源先显示所属平台与当前来源，展开后查看格式、码率和尝试记录；没有确认的信息仍显示未知状态。音质入口保留原能力和失败反馈。

歌词的译文、字号和跟随操作集中显示，窄屏按需要换行。滚轮、拖动或键盘浏览会暂停跟随；操作结束后无操作三秒，使用最新播放时间平滑回到当前句。拖动未结束、惯性仍在运行或正在调整歌词字号时不会抢回。手动“回到当前歌词”、点击带有效时间的歌词和切歌仍按原规则处理；自动回位不会 seek 或开始播放。

没有歌词、纯文本歌词、加载失败、切歌中和不能定位的行保持各自状态。制作人、编曲等文字属于歌词原始内容，不因版式调整删除。播放失败提示保留真实原因与当前可用动作；提示文字更明确不代表播放恢复算法或外部歌曲可用性已改变。

## 音源管理和编辑保护

“设置 → 音源”保留固定20项目录和高级管理入口。首次启动在首帧后准备固定版本，先核对脚本字节与 SHA-256，再受限初始化；离线不阻塞启动。安装包只带目录、版本、哈希与许可依据，第三方脚本正文不随包分发。

高级管理的播放策略保留下拉交互：点击原控件展开选项，支持方向键、Enter、Esc 和点击外部关闭。选中不推动下面列表，菜单与触发位置关联。启用、首选、排序、检查、更新、导入、HTTP 音源以及保存功能继续使用原设置。全新配置默认官方优先、自动尝试已启用候选、第三方下载关闭；升级不重置既有策略。

已停用或删除的项目不会因后台重试恢复。播放中的后台准备结果等待安全边界生效，管理页的草稿不会被自动刷新覆盖。准备成功仅表示目录与初始化阶段完成，不保证所有歌曲、音质或下载均可用。Windows 依赖有效的 WebView2 Runtime；Android 脚本宿主需要 Android 8.0 以上和具备隔离能力的 Android System WebView。

从音源、HTTP 音源、智能歌单或导入页面切换主区、使用共用搜索或返回时，会检查未完成内容。音源页沿用原保存与放弃流程；智能规则及歌单导入只在有未保存内容时询问“继续编辑／放弃”，保存或解析中暂不允许离开。

HTTP 音源保存失败会保留当前页面和输入。其配置与凭据分步保存，如果最后的凭据保存失败，前面的配置可能已经保存；放弃页面不会撤销此前成功的配置写入。可保留当前输入重试，或重新打开后核对已保存的设置。

智能歌单会保护名称、关键词、平台、ID、条件、排序、数量与时长等全部编辑值。保存失败保留内容；保存期间继续输入的部分仍算未保存。新建规则首次保存后留在编辑页继续修改时，后续保存更新同一条规则。异步保存完成不会关闭后来打开的其他页面。

歌单导入保护原文本、匹配报告和待确认勾选。保存与产生当前结果的那次输入关联；改了输入但尚未重新解析时，保存原结果不会把新输入也算成已保存。本地分享链接可能在解析步骤已经真实写入我的歌单，成功后不会重复提示该结果未保存。未匹配项目和原文继续保留在报告中。

## 其他功能与兼容范围

设置继续分为播放与音效、外观、桌面歌词、音源、下载与缓存、账号、备份与恢复七区。睡眠定时、淡入淡出、五频均衡器、字体与背景预览、主题、关闭行为及托盘控制沿用既有功能。

3D 环绕继续使用 KEMAR HRTF 双耳处理，界面依据真实音频处理帧区分等待、应用中、生效与失败。它不包含头部追踪或 Atmos 对象解码。桌面歌词的开关、字号、颜色与位置锁定继续可用，Android 需要悬浮窗权限；Windows 桌面歌词不提供鼠标穿透或独立歌词字体设置。

用户音量在本次会话内保留，重启仍回到默认100%。下载管理保留进行中、已完成、失败分组以及真实任务动作，离线缓存单独管理。备份继续先确认摘要并生成恢复点，包含本地收藏、自建歌单、智能规则、统计与设置；账号凭据、音乐文件、下载缓存、外部字体背景本体和智能生成结果快照不随 JSON 迁移。

原 Mconnect 入口及 `pubspec.yaml` 的 `1.5.0+16` 保持；IK 独立版本源为 `ik-version.json`。新增导航及呈现选项默认关闭，由 IK 入口显式启用。现有公开方法、数据格式、Android 包名、稳定签名及 Windows 安装身份不因界面统一改名。内部 `yueyin_music.exe` 和历史资源目录名属于兼容标识，用户看到的品牌仍是 IK Music。

## 构建准备与检查

在仓库根目录使用 PowerShell。准备项目要求的 Flutter/Dart、Windows C++ 工具链、CMake、Inno Setup，以及 Android SDK、JDK17 和原稳定签名配置。SQLite 离线输入必须是与依赖版本对应、已核对哈希的正式构建输入。

先同步和检查独立版本：

```powershell
.\scripts\sync_ik_version.ps1
.\scripts\sync_ik_version.ps1 -Check
```

生成物为 `lib/video_app/ik/ik_version.dart`、`windows/runner/ik_version.h` 和 `installer/ik_version.iss`；0.6.2 对应 build13。不要通过更改原 Mconnect 版本或共享依赖锁来替代独立版本同步。

确定构建提交后，使用项目已解析的依赖完成格式、静态分析、无过滤完整回归、全部新增场景门及适用的原生门。常规命令为：

```powershell
dart format --output=none --set-exit-if-changed lib test
flutter analyze --no-pub
flutter test --no-pub -j 1
```

同一工作目录中的测试和构建应串行安排，避免同时改动构建输入；隔离检出或远端流水线可以使用同一冻结提交独立验证。受联网、账号或设备条件限制的项目应写清实际跳过或失败范围，组件门通过不能替代成品操作。导航、紧凑播放器、歌词跟随、菜单键盘操作、草稿保护、连续无障碍更新以及旧默认兼容都须纳入验收。场景与具体证据见[页面统一修订票据](../IK-Music-内嵌页面与歌词跟随修订.md)。

## Windows 与 Android 构建

Windows 正规入口为 `scripts/build_video_windows.ps1`，发行使用 `-Compact` 创建全新的隔离副本。调用方填写本机真实路径后执行；所需参数如下。

| 参数 | 含义 |
| --- | --- |
| `-FlutterSdk` | Flutter SDK 根目录 |
| `-DependencyDirectory` | Windows 音源宿主依赖与原生门输出目录 |
| `-BuildDirectory` | 本次尚不存在的隔离构建目录，与 `-Compact` 一起使用 |
| `-InnoCompiler` | Inno Setup 编译器，缺失时脚本只生成便携 ZIP |
| `-SqliteBinaryDirectory` | 可选，正式核对过的 SQLite 离线输入目录，仅用于隔离副本 |
| `-SpatialAudioDll`、`-SpatialAudioSha256`、`-SpatialAudioLicenses` | 启用既有 HRTF 的同次音频 DLL、精确哈希与完整许可证目录，应成组提供 |
| `-Python` | HRTF 实际信号验收使用的 Python |

脚本在构建前检查版本，执行 Windows 音源、窗口、托盘、音频及安装迁移所需的门；音频替换先核对哈希和许可，再通过实际信号验证。交付目录包含完整运行依赖、图标、宿主、许可证、平台图标来源、安装迁移脚本及本指南，不能只拷贝 EXE。

Android 正规入口为 `scripts/build_video_apk.ps1 -Compact -EnableSpatialAudio`，使用 `-FlutterSdk`、`-AndroidSdk`、`-Jdk`、`-SigningProperties`、`-ToolchainsRoot`、`-BuildDirectory` 和所需离线输入参数指定已准备的本机环境。稳定签名配置必须沿用既有文件；私钥和密码不放入源码、说明、日志或发行包。构建产物按 arm64-v8a、armeabi-v7a 和 x86_64 拆分，逐包核对实际版本、签名、单一 ABI、原生库和许可证。

精简只在隔离副本裁掉已确认不用的扫码依赖和旧大图，保留二维码显示、音频、凭据、路径及许可。原源码 `pubspec.yaml`、`pubspec.lock` 和共享依赖缓存保持。HRTF 使用现有处理链，不随包附加完整 FFmpeg 命令行程序；可重建音频源码与相应运行时许可须随同一次发行保留。

## 构建产物与发行核对

0.6.2的安装包与配套文件使用以下名称：

- `ik-Setup-0.6.2-x64.exe`：Windows 安装器。
- `ik-0.6.2-windows-x64.zip`：Windows 完整便携包。
- `ik-0.6.2-windows-manifest.json`：同次 Windows 文件清单。
- `ik-0.6.2-arm64-v8a.apk`、`ik-0.6.2-armeabi-v7a.apk`、`ik-0.6.2-x86_64.apk`：Android 三架构安装包。
- 同次可重建音频源码包、本指南与 `SHA256SUMS`：交付时一并记录名称、长度、来源与哈希。

在同一提交上完成构建后，先核对包内品牌、版本、图标、指南、实际文件清单、音频许可和签名，再做 Windows 与 Android 覆盖安装。首次启动前检查用户数据保护；启动后检查五主区、全部普通详情入口、播放器与队列往返、设置、菜单、草稿取消/保存、歌词跟随及无障碍连续操作。真实登录、歌曲播放、3D、桌面歌词和设备目录操作逐项记录环境及结果。

Windows 更新使用安装器沿用现有目录；便携版完整解压后运行 `yueyin_music.exe`。Android 通常选择 arm64-v8a，具体以设备架构为准并使用同一稳定签名覆盖更新。iOS/Linux 图标适配资源保留，安装包以发行页实际提供的平台为准。

发行前冻结交付文件、记录实际长度和 SHA-256，并核对仓库标签与构建提交一致；上传后逐附件重新下载核对全部名称、长度与哈希。包大小、签名核验及安装结果以对应构建的清单和验收记录为准，各版本的结果分别保留。
