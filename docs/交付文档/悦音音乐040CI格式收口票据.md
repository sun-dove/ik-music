# 悦音音乐0.4.0：既有CI格式检查收口票据

日期：2026-11-16。

## 问题与范围

修复依赖来源漂移后，远端静态检查通过，但既有CI命令`dart format --output=none --set-exit-if-changed lib test`仍失败：460个Dart文件中263个需要格式整理。该问题在本机用同版本Dart独立复现，主要属于既有上游文件，并非功能测试失败。本轮本地完整回归已1838通过、11项既有跳过。

这属于样式整理，不新增模块或复杂能力，无需另开功能设计。使用锁定Flutter 3.47.5自带的官方Dart格式化器，不手工修改这些共享模块的逻辑、公开签名、返回值或默认行为。调用方无新增接口适配需求；受影响的文件清单以独立格式提交的Git差异为准。

## 处理选择

- 增加格式豁免或关闭该门：会降低仓库已有检查，不采用。
- 运行同版本官方格式化器：会产生较大的纯排版差异，但保留全仓检查并防止之后继续积累，采用此方案。

## 可执行验收与回滚

先执行既有命令复现红门，再对lib与test运行官方格式化器，最后以相同命令验证零变更。静态检查和完整回归继续由远端工作流运行，Windows原生门在发行脚本中必须实际启用；不改变覆盖率下限、国际化预算或已有跳过项。

格式整理单独提交。若需回滚，可单独revert该格式提交，产品功能提交与稳定签名保持；这会恢复既有格式红门，不隐瞒该结果。Android与Windows最终发行仍使用整理后的源码重新构建。

官方格式化把三处原有单行if拆成多行后触发既有curly_braces_in_flow_control_structures提示；仅补上对应语句块花括号，条件和执行语句保持不变，并继续要求静态检查0 issue。

## 原有跨主机样例修正

Linux远端全量门又复现5个既有样例问题，本机Windows全量门此前通过。3个离线样例硬编码Windows盘符，Linux将其解析成相对URI；改用本机临时目录构成的绝对路径，保留原有file:、不走网络与恢复播放断言。一个不透明导航占位场景隐含假设Windows，现显式声明原场景的平台，并在结束时恢复；真实玻璃分支仍由原有独立门完整覆盖。一个绘制顺序场景把所有后代Stack当成唯一布局Stack，玻璃分支多出内部Stack后定位失败，现按既有MiniPlayerBar子节点精确定位被验布局，绘制顺序断言保持。

上述修改仅涉及4份正式测试文件，不改生产播放器、导航、文件URI处理或任何断言阈值，不增加跳过项。真实失败日志与本机同断言通过共同构成复现依据；回滚可独立恢复这些测试样例。
